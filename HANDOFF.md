## Accepted goal and current result

Independent low-memory literature plugin in Mappedinfo, integrated with DeepSeek Harness. Provides quick import/search, APA 7 clipboard, individual/full-library BibLaTeX export, continuous PDF reading, native persistent annotations, a typed evidence graph and one native Harness conversation per paper. Zotero is optional input, not a runtime dependency or canonical store for this plugin.

The accepted reading workflow uses one reference collection per question in the same native conversation in the plugin and Harness main page. New/updated, manually selected and all-user-note shortcuts add to that collection; later saved notes prompt explicit addition. Search, page filters and pagination preserve selection. Temporary selected PDF text can coexist with saved notes. Opening a paper creates or reuses a durable cold Session without starting an Agent or model call. Initial model selection follows the source conversation's public projection or Harness default; later choices belong to the paper Session. Automatic sending remains opt-in and off by default. Complete AI replies can be saved individually to PDF with native Session/message provenance.

Current source checks exact selected PDF versions and full source text before writing a private immutable snapshot. Metadata selection holds at most 1,000 notes with 240-character text/comment previews; source preparation defaults to 24,000 Unicode characters, configurable from 1,000 to 96,000, and rejects overflow rather than truncating. A frozen canonical token works through either native input or the plugin. The public Host pre-step extension logs exact source content using a generic `Paper Library` plugin context, with identity/version/hash metadata outside model text. Only that verified, durably flushed log evidence updates the native usage projection; queue acceptance or a plain user token alone does not. The projection retains at most 5,000 last-sent annotation versions and reports eviction.

The added intake requirement is implemented: drop/select multiple PDFs or paste links/DOIs to fetch, parse, name and save managed copies; embed an independent DSH adaptation of `paper-fetch-skill` named `paper-library-fetch`. The skill uses the calling session and plugin tools. Exact parsed-title evidence gates online bibliography enrichment; metadata-only acquisition and incomplete parsing remain explicit. No external browser/MCP fetch runtime is installed.

User capacity target is approximately 2,000 records and 1,000 PDFs. Source Zotero data and existing PDFs were not migrated or modified during implementation.

## Ownership and architecture

- `src/dsh_paper_library/`: disk SQLite/FTS5 catalog and short-lived PDF worker; annotations are read from managed PDFs, not database annotation rows.
- `src/bridge.mjs`, `citation-worker.mjs`, `citations.mjs`: bounded job dispatch, independent CSL/BibLaTeX work. Citation.js must retain explicit source citekeys; do not restore autogenerated author/year labels.
- `src/paper-fetch.mjs`, `import-pdf.mjs`, `http.mjs`: public acquisition, title-checked metadata enrichment, source receipts and raw streaming upload. Limits cover redirects/DNS, bytes, deadlines, concurrency and aggregate queued payload; never reinstate whole-PDF Base64 in the browser. `skills/paper-library-fetch/` is the packaged adaptation; provenance is in `docs/upstream-manifest.md`. Preserve its distinct runtime name: the upstream name is shadowed by the user's existing global skill in actual Harness sessions.
- `src/harness/`, `src/client/`, `cordis.patch.yml`: real Harness tool/model/authenticated-web integration and lazy pane. No Harness source fork/change.
- `src/local-state.mjs` stores bounded CAS-versioned records under the resolved DSH home, namespaced by the canonical library path. It uses private modes, cross-process locks, file/directory sync and atomic replacement; runtime peers reuse DSH home/atomic-write utilities. `web/local-state.js` owns asynchronous restoration, queued saves, conflict recovery and verified legacy migration. Durable records are never an LRU cache. Changing a library path changes its namespace; migration across moved libraries is not automatic.
- `src/harness/language-learning.mjs` resolves the paper Session model before generation, validates source-backed vocabulary, checkpoints results before idempotent merging, and replays completed request IDs without another model call. Pending/uncertain and failed requests have distinct recovery paths. `web/language-learning.js` owns per-paper language drafts, history and vocabulary review. Results are local records; adding them to a question prepares the correct paper's draft without sending it or changing its PDF.
- `src/harness/paper-chat.mjs`: stable paper-to-Session identity, cold Session preparation, exact reference context, native admission, log-confirmed usage and bounded history. `annotation-snapshots.mjs` stores immutable private source snapshots and request bindings; `paper-reference-resolver.mjs` resolves direct-user tokens through the public pre-step waterfall; `annotation-usage.mjs` folds verified source envelopes and hashes into the native Session projection. Standard PDF annotations remain authoritative.
- `src/client/conversation-context.mjs` owns revision-guarded main-composer draft/navigation and a 256 KiB reader handoff. `annotation-references.mjs` registers the official input reference source/codec and keeps only one on-demand snapshot inspector. Main-input chips preserve other text/references/attachments; refreshed drafts remain resolvable plain tokens with an inspector entry. The inspector uses additive `conversation.input.dock`, and main history retains the native generic context renderer.
- `web/`: framework-free interface. `pdf-reader.js` keeps at most three page raster/text layers and one serialized geometry/page request; distant pages retain geometry placeholders only. `reading-panels.js` owns nonmodal sidebars/floating chat, and `reading-shell.js` owns the contextual ribbon/fullscreen. Coordinator tests cover selected-paper identity, hidden chat polling and closed-panel restoration. Metadata/chat/language drafts are separate host-owned per-paper records capped at 256 KiB each, with a bounded client working set. Raw selection, annotation type/color and panel state join the bounded iframe handoff; host records take precedence over old handoffs. An open annotation editor prevents an external reference from navigating away until the reader finishes or closes it.
- `scripts/`: build, install/audit, fixture creation, validation and benchmarks. Private data/outputs are ignored.

## Known limits and next validation

Language output and suggested vocabulary need reader judgment. Generation sends the explicitly selected text to the paper's configured DSH model and consumes that model's quota; local persistence does not mean local model inference. Standalone preview can review records but generation requires DSH. Records are bounded at 256 KiB; saves below 60,000 UTF-8 request bytes use keepalive, while larger pending saves require the page to stay connected. Abrupt host/browser termination before acknowledgment cannot guarantee saving unsent text. Malformed or oversized legacy browser drafts remain in place with a migration error rather than being silently deleted.

**Accepted reference update (2026-09-14, implemented):** [Continuous annotation references](docs/annotation-reference-design.md) now documents current behavior. The accepted implementation adds additive selection, exact source budgets, frozen snapshots, logged usage and official input references. Automatic batch reading, a native per-user-message custom card, and automatic chip reconstruction after reload remain unimplemented. Do not revive the old replace-only selection or silent 40-note/1,500-character truncation in native chat.

**Accepted implementation complete:** automated, native integration, browser, scoped memory and existing-profile installation checks all pass. Follow the boundaries below for additional validation; they are not claims of real-library, WPS or provider-quality coverage.

1. **WPS viewing/saving:** native application automation failed to complete opening the synthetic copy. Validate standard highlights/comments and embedded metadata after WPS save on a copied file; do not claim WPS compatibility from PyMuPDF-only tests. Existing user documents were not edited.
2. **Real library:** benchmark a user-selected export/copy, including scanned/image-heavy PDFs and long reading sessions. Keep total browser/host/worker memory separate. Do not infer Zotero's 3 GB cause from this implementation.
3. **Search:** title/author/DOI/citekey/tags/abstract only. Full-text indexing/OCR/embeddings are deferred; add an explicit on-demand pipeline and memory budget if requested.
4. **Migration:** JSON metadata batch cap2,000/32MB, process100 at a time; PDF250MB/2,000pages; one managed PDF per record. Export DB-only Zotero annotations into PDF or provide JSON positions. Collections, standalone notes and dynamic word-processor fields are not migrated. Duplicate PDFs are not automatically merged/replaced.
5. **Conversation coverage:** the reference update has automated, actual Host and 11-flow browser evidence, with the browser flows rerun after the workbench changes. The expanded native inspector was checked against viewport and PDF-frame bounds. Authenticated installed-host capability checks pass. Actual-library mutation testing and real-provider response quality remain outside the verified scope.
6. **Conversation limits:** inline history contains at most 20 committed user/assistant texts, 6,000 characters per message and 48,000 total. Full history, live tool output, approvals and stop controls remain in the main conversation. Cold reads close their observer and leave Harness's bounded prepared-session cache to its owner. First creation checkpoints title and blank-list metadata through the optional public cache service after the log is durable, without activating an Agent. Harness deliberately hides noncurrent zero-turn Sessions, labels the selected empty one “New Session” and hides its main header until prompting; the plugin's “Open main conversation” still opens it by identity. The paper title appears normally after the first message. Native Agents activated by main-page opening or prompting remain under Harness lifecycle management; no plugin-owned idle eviction is claimed. Archived paper Sessions produce an explicit error because the current public API has no unarchive operation. Moving the library directory does not migrate its deterministic paper-to-Session identity.
7. **PDF feedback:** explicit saves read a completed native assistant event on the server, require an attached PDF, and deduplicate by Session/message ID. The stored note records provenance and uses an empty annotation association list; the plugin does not infer which earlier annotation a later answer addresses. Older responses outside the inline history window cannot currently be saved from the inline UI. Actual provider usefulness and long-running conversation memory remain unmeasured. The standalone `ai_feedback`/`library_feedback` path remains for compatibility and is not the default Harness reading workflow.
8. **Acquisition:** direct public PDFs, Crossref/DOI, arXiv and generic citation metadata are supported. Publisher-specific authenticated/browser providers and OCR remain deferred. Exact parsed-title matching can decline enrichment for truncated or unusual titles; keep the review flag rather than guessing. Live network smoke used a public synthetic PDF; publisher and arXiv branches use deterministic transport fixtures.

Reopening deferred work requires a specific feature/data request, not a silent expansion during routine maintenance.
