The first was a genuine leak: dragging a line out of a node's connect handle appended a fresh dashed preview path on every `pointermove` and never removed the previous one, so a 40-step drag left 40 identical paths in the edge layer for the browser to repaint (measured: 11 paths mid-drag → 1 after the fix). The second was the persistent-scene property Excalidraw relies on: `render()` discarded and rebuilt the whole node/edge tree, which cost ~1,200 element creations and ~3,700 `setAttribute` writes at 150 nodes for every selection, rename or save-status change. It now reconciles keyed by board id — create what is new, update in place, remove what left — and the attribute writes are conditional, because writing the same string still invalidates the element. The JS time was never the problem; the mutations were.

The same measurement applied to a drag found the pattern once more: `redrawGeometry` — the cheap path — rewrote every node and every edge on every pointer move. It now takes the ids the gesture touched (a move passes the dragged set, a resize its one node, a bend-point drag the two endpoints, and the connect gesture, which moves nothing on the board, no longer calls it at all). Dragging one node on a 150-node board: **1,504 → 9.3** attribute writes per pointer move, median frame 8.1 → 7.9 ms, p95 11.1 → 9.8 ms. The frame is dominated by the browser laying out and painting a 150-node SVG, so the win is the ~300 element invalidations removed per frame rather than the JavaScript time; the whole-board pass is still one call away for a layout or a marquee.

One more redundant write fell out of the same measurements: `applyView` rewrote the transform of the group holding the entire scene on every drag frame, although moving a node does not move the view; it now writes only on a real view change, keeping the whole scene out of style and paint invalidation on those frames.
