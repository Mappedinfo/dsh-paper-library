## Accepted goal and current result

Independent low-memory literature plugin in Mappedinfo, integrated with DeepSeek Harness. Provides quick import/search, APA 7 clipboard, individual/full-library BibLaTeX export, one-page PDF reading, native persistent annotations, an explicit literature relation graph and one native Harness conversation per paper. Zotero is optional input, not a runtime dependency or canonical store for this plugin.

The accepted reading workflow now uses the same native conversation in the plugin and Harness main page. Opening a paper creates or reuses a durable cold Session; it does not start an Agent or a model request. The first Session seed uses the source conversation's public model projection when available, otherwise the Harness default. Later model changes belong to that paper's conversation. Selected PDF text and saved annotations can become a main-composer draft or a queued native prompt. Sending may be explicitly automated after a new annotation is saved. Complete AI replies can be saved individually to PDF with their native Session/message provenance.

The added intake requirement is implemented: drop/select multiple PDFs or paste links/DOIs to fetch, parse, name and save managed copies; embed an independent DSH adaptation of `paper-fetch-skill` named `paper-library-fetch`. The skill uses the calling session and plugin tools. Exact parsed-title evidence gates online bibliography enrichment; metadata-only acquisition and incomplete parsing remain explicit. No external browser/MCP fetch runtime is installed.

User capacity target is approximately 2,000 records and 1,000 PDFs. Source Zotero data and existing PDFs were not migrated or modified during implementation.

## Ownership and architecture

- `src/dsh_paper_library/`: disk SQLite/FTS5 catalog and short-lived PDF worker; annotations are read from managed PDFs, not database annotation rows.
- `src/bridge.mjs`, `citation-worker.mjs`, `citations.mjs`: bounded job dispatch, independent CSL/BibLaTeX work. Citation.js must retain explicit source citekeys; do not restore autogenerated author/year labels.
- `src/paper-fetch.mjs`, `import-pdf.mjs`, `http.mjs`: public acquisition, title-checked metadata enrichment, source receipts and raw streaming upload. Limits cover redirects/DNS, bytes, deadlines, concurrency and aggregate queued payload; never reinstate whole-PDF Base64 in the browser. `skills/paper-library-fetch/` is the packaged adaptation; provenance is in `docs/upstream-manifest.md`. Preserve its distinct runtime name: the upstream name is shadowed by the user's existing global skill in actual Harness sessions.
- `src/harness/`, `src/client/`, `cordis.patch.yml`: real Harness tool/model/authenticated-web integration and lazy pane. No Harness source fork/change.
- `src/harness/paper-chat.mjs`: stable paper-to-Session identity, cold Session preparation through public persistence services, native prompt admission and bounded history. `src/client/conversation-context.mjs` owns main-composer draft/navigation and a bounded reader-state handoff across the sidebar remount; it preserves existing draft text, reference chips and attachments.
- `web/`: framework-free interface; one rendered PDF page retained; metadata/graph/annotation results capped.
- `scripts/`: build, install/audit, fixture creation, validation and benchmarks. Private data/outputs are ignored.

## Known limits and next validation

1. **WPS viewing/saving:** native application automation failed to complete opening the synthetic copy. Validate standard highlights/comments and embedded metadata after WPS save on a copied file; do not claim WPS compatibility from PyMuPDF-only tests. Existing user documents were not edited.
2. **Real library:** benchmark a user-selected export/copy, including scanned/image-heavy PDFs and long reading sessions. Keep total browser/host/worker memory separate. Do not infer Zotero's 3 GB cause from this implementation.
3. **Search:** title/author/DOI/citekey/tags/abstract only. Full-text indexing/OCR/embeddings are deferred; add an explicit on-demand pipeline and memory budget if requested.
4. **Migration:** JSON metadata batch cap2,000/32MB, process100 at a time; PDF250MB/2,000pages; one managed PDF per record. Export DB-only Zotero annotations into PDF or provide JSON positions. Collections, standalone notes and dynamic word-processor fields are not migrated. Duplicate PDFs are not automatically merged/replaced.
5. **Conversation coverage:** the updated browser path from saved annotation to main-composer draft, inline send, shared main history, return to the same PDF/draft, and explicit reply-to-PDF save is verified with synthetic documents. The existing installation's authenticated capability and asset checks also pass, and its native PWA shows the updated entry and opens the library pane. Actual-library reading and real-provider response quality remain outside the verified scope.
6. **Conversation limits:** inline history contains at most 20 committed user/assistant texts, 6,000 characters per message and 48,000 total. Full history, live tool output, approvals and stop controls remain in the main conversation. Cold reads close their observer and leave Harness's bounded prepared-session cache to its owner. First creation checkpoints title and blank-list metadata through the optional public cache service after the log is durable, without activating an Agent. Harness deliberately hides noncurrent zero-turn Sessions, labels the selected empty one “New Session” and hides its main header until prompting; the plugin's “Open main conversation” still opens it by identity. The paper title appears normally after the first message. Native Agents activated by main-page opening or prompting remain under Harness lifecycle management; no plugin-owned idle eviction is claimed. Archived paper Sessions produce an explicit error because the current public API has no unarchive operation. Moving the library directory does not migrate its deterministic paper-to-Session identity.
7. **PDF feedback:** explicit saves read a completed native assistant event on the server, require an attached PDF, and deduplicate by Session/message ID. The stored note records provenance and uses an empty annotation association list; the plugin does not infer which earlier annotation a later answer addresses. Older responses outside the inline history window cannot currently be saved from the inline UI. Actual provider usefulness and long-running conversation memory remain unmeasured. The standalone `ai_feedback`/`library_feedback` path remains for compatibility and is not the default Harness reading workflow.
8. **Acquisition:** direct public PDFs, Crossref/DOI, arXiv and generic citation metadata are supported. Publisher-specific authenticated/browser providers and OCR remain deferred. Exact parsed-title matching can decline enrichment for truncated or unusual titles; keep the review flag rather than guessing. Live network smoke used a public synthetic PDF; publisher and arXiv branches use deterministic transport fixtures.

Reopening deferred work requires a specific feature/data request, not a silent expansion during routine maintenance.
