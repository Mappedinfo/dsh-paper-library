# 从实验源码生成画板流程

交付可直接导入的 `.json` 文件，以及实际改过的源码、补丁或展示副本。制图使用 EqTrace 的 Python 静态规则。解析和检查都可在本地完成，无需导入用户模块、安装 PyTorch 或启动训练。

## 先看原图

找到用户要展示的训练入口、模型类和实际被调用的方法，核对调用点与数据加载方式。只分析网络时用 `--model`，训练入口用 `--entry`，两者在同一文件时可只传 `--entry`。多模型或自定义方法用 `--class Class.method` 明确选择。训练和模型分文件时保留项目内的相对路径、模块名和 import 关系。

从本技能目录执行下面的命令。将 `PROJECT` 设为用户源码根目录的绝对路径，将 `FLOW_JSON` 设为本次输出的新文件路径，按实际文件替换示例参数。技能通过符号链接安装时，`pwd -P` 可找到随插件分发的工具。

```sh
FLOW_SKILL="$(pwd -P)"
FLOW_PYTHON="$FLOW_SKILL/../../.venv/bin/python"
[ -x "$FLOW_PYTHON" ] || FLOW_PYTHON=python3
"$FLOW_PYTHON" -I -B "$FLOW_SKILL/../../vendor/eqtrace/run.py" \
  --root "$PROJECT" --entry train.py --model model.py --class MyModel \
  --out "$FLOW_JSON"
node "$FLOW_SKILL/scripts/check-flow.mjs" "$FLOW_JSON"
```

使用 Python 3.11+。示例优先沿用插件已有的解释器；若回退到旧系统 Python，将 `FLOW_PYTHON` 设为本机已有的 3.11+ 解释器。已有独立 EqTrace 时可用 `eqtrace paper-flow` 加同一组参数。已有 JSON 可直接从检查开始。检查器调用画板的导入器和渲染器，会逐图检查完整图和已有的阶段总览，列出节点、连线、解析诊断及部分或全部形状未知的节点。对照用户要看的关键操作与张量，查看节点的 `evidence`（文件和行号）、`tensor`、`config` 以及所属流程的 `diagnostics`。原图已足够时直接交付。

## 按证据补注释或适配

- **缺输入轴。** 从模型调用、数据加载器、接口说明或已有测试找轴序证据。在选中方法的输入参数上用 `typing.Annotated` 标出它。例如已有批处理契约说明 tokens 的第 0 轴是批次、第 1 轴是源序列，可将 `tokens: torch.Tensor` 改为 `tokens: Annotated[torch.Tensor, "B,S"]`，补上 `from typing import Annotated`。保留原有类型及元数据。训练端可在批迭代器参数写 `Iterable[tuple[Annotated[torch.Tensor, "B,8"], Annotated[torch.Tensor, "B,1"]]]`，前提是两个宽度和顺序均有依据。源码中的中文注释可以解释轴的含义和出处；解析器从参数类型注解取形状。
- **只知道部分尺寸。** 字母表示可复用的符号轴，数字表示有证据的固定轴长，`?` 表示一个未知轴，首位 `...` 表示任意数量前导轴，`[]` 表示标量。秩未知时保留未知。嵌入层的词表大小不能给出序列长度，配置的最大长度或训练批大小也不能代替该次输入的轴长。
- **调用未展开。** 先选能直接解析的真实方法。例如实现都在 `MyModel.encode` 时，显式选择它，并用标题说明图的范围。若仍需展示调用者，可把相关源码保留相对布局复制到展示目录，只改有证据的部分。例如同类纯辅助方法唯一实现为 `return self.proj(x)`，且调用目标固定、无覆盖和额外动作时，可在展示副本把该处 `self.project(x)` 展开为 `self.proj(x)`。在副本注释或交付说明中标明原文件、方法和原行号，保留可重生成的适配源码。新图的 `evidence` 指向副本。
- **动态行为。** 对运行时分派、分支、循环、原地修改或共享状态，保留真实顺序、数据依赖和副作用。不能确认等价的地方保留解析器的 `unresolved`、候选边或未知形状，注明具体位置及缺什么证据。训练图中的源码顺序、条件路径和可能零次的循环都以静态含义展示。

用户明确要修改源码且项目允许时，在原文件做最小修改。仅请求展示、项目限制改动、类型注解参与运行时反射或改写可能改变行为时，使用单独的展示副本或补丁。不要生成占位的前向计算、绕开真实分支、手画缺失边或修改导出 JSON 来消除诊断。

若用户要的是**画板上可读的节点讲解**，从已生成的 JSON 派生一份带说明的文件。按流程、节点 ID、操作和源码位置找到节点，把有依据的中文解释追加到 `node.detail`，读者可在「编辑流程」点击节点查看。要让解释出现在论文插图的节点浮窗，追加到该节点已有的 `node.tensor.note`。例如输入契约和线性层都已核实，可写「将每个源词的 6 维嵌入投影为 2 维输出，批次轴和序列轴保持不变」。保留原来的说明、证据、形状和诊断，区分 agent 讲解与源码原句。原节点在「全部节点」可见，阶段总览中只给能由该组成员共同支持的结论加说明。对最终带注释文件再运行检查器。

## 有实际输入时

从同一次模型调用对应的数值 `.npy` 文件头或已有运行记录读取形状，再按模型输入参数的轴序绑定符号。例如源码已声明 `source` 为 `B,S`，该批次文件头为 `[4,12]`，可报告 `B=4`、`S=12`。仅有源输入时，保留目标序列长度 `T` 为未指定。相同符号跨输入须一致，冲突时指出文件及轴，保留已验证的绑定。

临时查看时，在「代码与数据 → 关联实际输入」选择对应文件即可。用户要求把可核对的轴长随 JSON 交付时，在对应的 `flows[]` 项的 `observed_dimensions` 记录每个实测值及来源，例如 `{"B":{"value":4,"source":"source-batch.npy"},"S":{"value":12,"source":"source-batch.npy"}}`。只携带必要的轴长和可辨认的来源，不复制原始样本。示例值另用 `example_dimensions`，中间节点的形状仍为静态推导。文件头和符号绑定的现成实现位于插件的 `src/paper-flow/tensor-data.mjs`。

## 验证并交付

改完后从实际交付的文件重新生成 JSON，再运行上面的检查。核对关键输入、一个中间操作及输出；训练图另核对用户关心的前向、损失、更新或分支位置。只补形状时核对操作拓扑未变；展开辅助方法时用原调用位置核对替换范围和前后依赖。改变类型或表达式且已有相关轻量测试时，按项目约定运行。解析成功和 SVG 渲染通过只证明可展示。

报告文件路径、图中展示的类或训练入口、具体补了什么和仍未知的节点。用户在「画板 → 论文流程 → 比较 → 导入 JSON」打开文件；也可在「代码与数据 → 从源码生成」选择适配后的源码。界面每份 Python 源码最多 256 KiB，每份输出 JSON 最多 192 KiB，单图最多 100 节点、200 条边。超限时选择真实子入口并标出覆盖范围。Agent 交付流程文件，读者决定导入哪张画板；`library_board` 处理自由画板，论文流程有独立存储。
