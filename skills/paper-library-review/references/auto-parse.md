# 自动解析：证据图谱评审草稿

本插件在后台整理一篇已关联 PDF 的论文时，除了图谱草稿与精读笔记草稿，还会运行一次**受限的证据图谱评审**，产出「证据图谱评审」待审草稿。本文件说明它的数据来源、预算、产出结构与复核方式；方法论本体见 `evidence-atlas-review.md`。

## 触发与预算

- 触发：`paper_analysis_start` 的作业在完成各批图谱与精读笔记后运行；客户端以 `review:false` 关闭，或把实时偏好 `auto_review` 关掉。
- 一次运行至多 **1 次**模型调用（与图谱、笔记阶段分开计数）。
- 输入材料复用已提交的批次图谱记录（与精读笔记同一份 bounded 投影，≤24,000 字符），**不额外读取 PDF、不做 OCR**。
- 输出：`title` ≤40 字符，`body` ≤64,000 字节；作业用确定性 `request_id`（`analysis-review-<hash>`），重复提交不会重放模型。
- 该阶段失败只记录原因，不会让整理作业失败，也不会覆盖已保存的图谱与笔记草稿。

## 产出结构（Markdown 正文）

草稿正文必须包含并可被界面直接阅读：

```markdown
# 证据图谱评审：<论文短题>
## 1. 快速判定            # 一句话结论 + 成熟度 + 结论标签
## 2. 案例拆解            # 每个案例的 O/T/I/Y/C/M/Q/E 编码（缺失留空，不合并案例）
## 3. 案例 × 需求状态矩阵 # satisfied/failed/unknown/not_comparable/not_applicable/unassessable
## 4. 归因标注            # author_claim / reported_result / reviewer_inference
## 5. 联合覆盖审计        # 联合声称是否由同一案例支撑；拼接项逐条列出
## 6. 形容词操作化        # 每个能力形容词的定义、指标、条件，或标注为作者声称
## 7. 本文最多能声称
## 8. 本文不能声称
## 9. 若要声称更强结论，还需要
## 10. 修改清单           # P0 立即修复 / P1 重要修改 / P2 后续优化，含验收标准
```

草稿一律为 `needs-review`：模型不能接受自己的草稿，也不能改写知识正文；是否采纳由读者在库界面决定。草稿来源（`source_ids`）保留被引用原文的快照，便于逐条核对页码与逐字引用。

## 证据边界

- 每个承重判断必须带归因；摘要里的形容词只能标注为 `author_claim`，不能当作实测能力。
- 缺失必须结构化：`not_reported` 要写明检查范围，`unknown` 既不进通过也不进失败。
- 联合声称必须由**同一案例、同一配置、同一协议**同时支撑；否则降级为分项声称。
- 不编造页码、数字、作者或引用；报告中的每条证据都应能在来源快照里找到对应文字。
- 这是生成式评审草稿，不构成独立评审证据，也不代表模型读完了全文或复现了结果。

## 复核方式

1. 打开论文 →「后台整理」→ 展开「证据图谱评审」草稿；
2. 在「知识笔记」工作流中逐条核对案例、归因与状态矩阵；
3. 需要正式报告时按 `output-template.md` 整理，需要评分时按 `review-rubric.md` 的 100 分量表；
4. 发现事实错误的条目直接否决草稿或改写，原始来源仍保留在 `knowledge_sources`。

## 个人覆盖层（不在本仓库）

个人阶段标准、目标期刊、评分偏好与个人项目信息**不属于本插件**，请放在自己的私有仓库（一个本地笔记或笔记库目录即可），并把 DSH 配置 `reviewProfile` 指向那个文件：

```yaml
# 目标 profile 的 cordis.patch.yml（示例）
- insert:
    - id: paper-library
      name: '@mappedinfo/dsh-paper-library'
      config:
        library: /path/to/library
        reviewProfile: /path/to/private-notes/review/personal-overlay.md
```

- 仅在显式配置后读取；路径必须是存在的绝对文件路径，读取上限 8,000 字符，超过会被截断并在草稿中注明。
- 覆盖层只影响措辞、阶段标准与侧重；不能放宽“逐字引用、真实页码、归因三态、联合覆盖”这些硬约束。
- 覆盖层与通用方法冲突时以覆盖层为准，并在报告中写明差异来自本地覆盖层。
