# 从来源到可读笔记

这是 Paper Library 的原创方法适配，采用项目 MIT 许可。笔记正文由插件保存在资料库的 Markdown 文件，结构化身份与来源关系由目录管理；不要使用浏览器存储、另建私有目录或直接编辑数据库。继续使用当前 DSH 模型。

对象可以是文献、独立数据集或具体版本。先通过 `library_resources` 定位，再使用 `library_knowledge` 的 `source_list` 和 `source_get` 读取用户明确选择的完整来源；参数为 `operation` 和 JSON 字符串 `input_json`。来源不足时保留未核验内容，不扫描全文库或自行启动额外模型。

对需要形成完整解释的对象，正文按读者理解顺序组织：一句话定义、贯穿的具体例子、内容与机制、发展与现状、同一任务下的替代选择、上下游、适用场景、限制与来源。短登记不强制扩写成长笔记；来源不支持历史或比较时明确说明。数据集应解释记录单位、字段、时空覆盖、版本、获取方法、许可状态及它适合回答的问题。数值、日期与性质须绑定来源；抽样统计不冒充全量数据事实。

原文摘录、来源报告、作者推断和模型解释应可区分。引用来源 ID 并保留现有 citekey，不手写第二份题名、作者、年份或 DOI。对于动态数据，记录实际快照／版本，未知项保持未知。不把下载成功或官方元数据当作数据质量认证。

生成后使用 `library_knowledge` 的 `draft_put` 保存提案，`input_json` 内容为：

```json
{"entity":{"kind":"dataset","id":"用户选择的ID"},"mode":"note","source_ids":["明确选择的来源ID"],"title":"知识页题名","body":"Markdown 正文与来源ID引用","nodes":[],"edges":[],"assertions":[]}
```

使用 `draft_get` 读回检查。所有 AI 笔记先标为待审阅；请用户在界面阅读、修改并保存到知识正文。模型工具没有接受草稿或覆盖正文的权限。已有笔记可通过 `note_list`／`note_get` 读取，再提出新草稿；不把旧正文内容悄悄替换。

对完成的笔记，核对定义可读、例子具体、比较标准一致、每个主张具有实际来源或明确推断标记。图谱校验和标题齐全不能证明读者已经理解。仅当比较确有用途时建立综合笔记，不为每篇相关论文复制一整页数据说明。

## 每次论文分析的数据与方法必查项

保留原有问题和输出结构，逐项检查下面三组；看似无关也要给出本次阅读范围内的「未说明」或有理由的「不适用」，不能直接跳过。一个回答绑定一份数据、版本/子样本及一种用途，跨题复用身份与出处，不重复造同义数据/方法节点。

- **human mobility 数据**：实际用了什么（原名、提供者、版本；观测/代理/合成），覆盖哪里、何时、哪些对象/样本；记录单位及原始/处理后时空粒度；如何采集、抽样、清洗、匹配、插补、标注、聚合与质量检查；原始数据/处理产品是否公开、获取入口与许可/申请/付费限制。
- **建筑/建成环境数据**：同样核对来源、范围、粒度、制作与获取；明确轮廓、楼高/楼层、用途、年代、室内/BIM、街景/遥感或其他代理信息。静态人口、POI、土地利用不自动等于实测出行或单栋建筑数据，代码开放不等于数据开放，论文链接不等于已经验证能下载。
- **如何使用及方法命名**：逐份数据区分训练 train、验证 validation（调参/选模）、最终测试 test、校准 calibration、推断条件/输入、参数来源/先验、空间约束与背景。原文只说「验证」而无法分清阶段时保留歧义；固定参数不等于模型训练。方法给原名、已报告全称/缩写、作者明确的命名理由及其与机制的联系；读者的机制解释另标，未说明的缩写或命名来源不猜。

每个肯定判断附来源/页码；局部未提及不等于全文未使用或不公开。全文分析的新请求默认使用 `reading-questions-v5` 的36题（原23题加13题）；指定子集时明确其覆盖不足，不声称全部已问。旧请求沿用冻结快照，不自动重跑、重计费或回填现有笔记/原生 PDF 划线与问答。

## 将问答放回 PDF 时

只有任务明确要求写原生 PDF 批注时才计划写入；知识笔记草稿不自动变成 PDF 修改。默认一注一个原子主问题，分别绑定最相关局部证据；来源、版本/子样本、对象或用途不同要拆分。同一段真实支持多题可以同锚点，但保留独立问答，不堆成长备注，也不为分散而强绑。

跨页证据逐项引用，主锚点必须支持主问题。缺失结论与全篇总结明确标 `context-not-evidence` 或 `unanchored`，不冒充局部证据。唯一真实原文、物理页码及 quad 都要核验；多个换行 quad 可属于一个引文，重复出现须扩大到唯一上下文，不能直接收取全部搜索命中。覆盖审查逐题核对问题语义与证据，不只数题号或批注数量。

执行门槛：每次新建或改写原生 PDF 问答前，必须采用仓库 `docs/question-placement.md` 的逐题计划，并先运行只读 `dsh_paper_library.placement_preflight`；临时手写计划和少量示例也不能跳过。退出码非0或报告 `ok:false` 时停止写入并修复计划；拿不到该预检时报告阻塞，不改用未检查的批量脚本。通过后仍须人工或明确的语义审阅逐题核对证据。它不是自动语义判分，也不替代现有写入器的备份、锁内版本检查与原子替换。改写旧批注前精确限定批次/稳定ID及内容快照，保留非目标批注、正文和回复关系；并发变化立即停止。旧批次不自动重跑或修复。

在仓库根目录执行：`PYTHONPATH=src .venv/bin/python -m dsh_paper_library.placement_preflight plan.json sources.json`。`sources.json` 仅含明确指定的来源ID到本地PDF路径映射。此为执行纪律，不表示运行中的写入器已强制集成；不要向用户声称旧批次已自动修复。
