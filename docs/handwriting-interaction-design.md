# 关联手写：结束、预览与定位

2026-10-04 · **拟议交互，尚未实现。** 本文供原型与后续开发使用；代码审计只能确认等待关系和现有入口，不能证明耗时来源或改进幅度。

读者在 PDF 上给一条文字批注写完想法后，应能立刻继续阅读，在批注卡片看到原笔迹，并从笔迹返回它在页面上的位置。“完成手写”只结束输入；保存和识别各自反馈进度。

## 一条阅读路径

读者高亮“这一结论仍缺少跨城市验证”，在旁边写“换一个城市还成立吗？”并画箭头。点 **完成手写** 后，工具立即回到高亮，页面停在原处；卡片同步出现原笔迹，显示“正在保存”。读者可以继续读下一段。确认写入后状态变为“已保存”，识别另显示“正在转文字”。

稍后点击卡片的摘录，页面定位原文；点击笔迹预览，则定位手写区域并描亮 1.8 秒。手写分布在两处时，卡片提供“笔迹 1 / 2”的区域选择。点“返回刚才位置”回到跳转前的阅读位置。保存失败只在对应卡片显示“保存未确认 · 重试”，原笔迹和继续阅读的能力都保留。

## 四组独立状态

| 维度 | 状态 | 可见反馈与约束 |
| --- | --- | --- |
| 输入 | 阅读／手写／本笔尚未结束 | 结束手写只退出输入模式并冻结已完成笔画；尚未抬笔时提示先抬笔，不能偷偷截断当前笔画 |
| 保存 | 暂存中／已暂存待写入／写入中／已保存／待确认／暂存失败 | 卡片显示对应状态；只有 PDF 写入确认才称“已保存”。保存错误不锁住阅读或其他已就绪批注 |
| 识别 | 未请求／排队／识别中／待校对／失败／笔迹已更新 | 只识别已确认的完整几何版本；沿用视觉模型和已有请求身份，保留费用提示与人工校对保护 |
| 定位 | 无／加载目标／临时聚焦 | 仅影响当前视图。新定位覆盖旧定位，用户滚动可取消待执行跳转和临时聚焦 |

“完成手写”在本地快照接收后恢复原工具，不等待 PDF、卡片重读或识别。没有新增笔画时直接退出，不生成保存批次。未收到暂存确认时显示“正在暂存，请暂勿关闭”；可以继续阅读，但不能承诺此时的崩溃可恢复。主机确认接收后，即使阅读 iframe 被收起或销毁，保存任务仍由主机继续处理。

## 冻结批次与主机暂存队列

活动笔画、待保存批次和已保存 PDF 必须分开。每批只包含新完成的笔画，不反复提交整组累计笔迹。冻结记录包含 `paperId、parentId、page、annotation_id、revision、paths、width、color`；自由手写省略 `parentId`。原始重试身份与几何从首次尝试起不可改变，新笔迹进入下一批。

队列按论文保存，批次保留父批注归属；同一 PDF 串行写入，首版全局也只运行一个写入任务。主机先原子确认暂存，再调用 PDF 写入；确认写入与队列完成分别记录。页面重新挂载从主机恢复任务，不把 iframe 内存中的 Promise 当作任务存续保证。复用既有私有状态目录、版本校验和冲突处理；不得静默覆盖其他浏览器的队列。

建议首版采用以下容量保护，均为**拟议限制**：

| 层级 | 上限与检查时机 |
| --- | --- |
| 单批 | 沿用现有 64 笔／4,096 点／128 KiB 上限，冻结前检查 |
| 单论文队列 | 最多 8 个未完成批次，完整状态记录不超过既有 256 KiB 上限 |
| 全部未完成队列 | 最多 4 篇论文／16 批／1 MiB，任一先到即停止接纳更多笔迹；完成记录另作有界清理 |
| 同一父批注 | 已保存笔迹与排队批次合计仍遵守现有 64 组／128 笔／8,192 点／256 KiB 几何限制，主机接纳时预留容量 |

容量不足保留已经接收的笔迹，提示先处理待保存项；不自动删除、截断或以新笔迹覆盖旧批次，也不阻止阅读。单个尚未获得主机确认的活动批次继续使用现有父窗口交接；交接中保存队列引用，不把所有已持久队列复制进 256 KiB 阅读快照。

失败语义必须区分：

- **暂存失败**：保留当前内存及可用父窗口交接，显示“尚未暂存”；暂停接纳下一份未确认批次，允许阅读、重试和导出。
- **PDF 结果不明**：保留原 `annotation_id` 和完全相同的请求，按原身份核对／重试；不得生成新 ID 重写。阻塞本论文后续写入，其他论文仍可推进。
- **刷新失败**：PDF 确认结果保持“已保存”，只提示显示待更新，保留覆盖层，不重新写入 PDF。
- **父批注删除或身份冲突**：保留批次并提供恢复／导出，不自动改挂到别的批注。放弃重试不等于删除可能已经写入 PDF 的笔迹。

## 卡片中的笔迹与两个定位入口

卡片依次展示摘录、读者评论、原笔迹预览、识别文字。预览由 `linked_ink.annotations.paths` 与待保存批次直接生成有界 SVG，保留颜色、笔宽和相对位置；用保存 ID 去重，用几何版本和待保存修订号缓存。首屏只生成可见卡片，不为预览重新请求整页截图。识别失败时原笔迹仍完整可看。

摘录和笔迹各自是有标签、可键盘操作的入口：**定位原文**沿用父批注矩形；**定位笔迹**使用笔迹自己的几何。空白卡片区域保持现有父批注定位行为，操作按钮不触发额外跳转。Ink 子批注仍嵌在父卡片内，不增加主批注计数。

当同一批注的笔迹相距较远时，预览按空间区域分页或分块，提供“全部／笔迹 1／笔迹 2”；区域按位置稳定排序，不以自动保存批次切分用户看到的内容。选择某一区域只定位对应路径；“全部”在当前缩放下优先让所有目标可见，范围过大时让读者选择区域，不擅自改变阅读缩放。点状笔画也须保留可点击范围。

## 临时定位与返回

建议增加统一视图接口 `revealRegion({paperId,page,rects,kind,focusId})`，由原文或笔迹入口生成目标。笔迹边界包含笔宽和适量留白，按页面展示坐标计算，适配旋转、缩放及横向滚动。定位采用最小必要滚动；需要居中时同时处理两个方向。

目标到达后用轮廓或笔迹外缘强调 **1.8 秒**，不新增高亮批注、不改原颜色、不写入 PDF；减少动态效果偏好下取消滚动动画，保留静态短时轮廓。范围较大时避免用实色矩形遮住正文。

每次跳转递增请求序号；异步结果只有仍对应当前论文和最新请求才可滚动或绘制轮廓。用户滚轮、手指拖动、滚动条或导航按键取消待执行跳转及当前轮廓；不能把程序自身产生的滚动误当作用户取消。活动笔画／选文手势期间暂缓跳转。

一次连续定位过程保留最初的 `{paperId,page,页面内位置,横向位置,zoom}`，显示一次“返回刚才位置”；后续定位只替换目标，不覆盖这份返回点。手动滚动可结束聚焦，但返回入口保留；明确换论文后不再由旧异步结果导航。返回时按保存的页面相对位置恢复，适应窗口尺寸改变。

## 页面更新与验收目标

每批写入成功后先更新卡片与矢量覆盖层，不立刻重绘整页。合并同页更新，在输入空闲后刷新；未显示的页只标为待更新，进入视口时再读取。新图像确认包含相应保存 ID 后才撤掉该批覆盖层。替换图像和文字层前再次确认没有活动笔画或选文手势，避免恢复阅读后又被后台刷新取消标注。

以下是**后续验收目标，不是当前实测成绩或对所有设备的保证**。先用合成文档、固定 Chrome 版本和记录过的机器建立基线；冷页面、模型和主机故障单独统计。

| 操作 | 建议目标 | 验证方式 |
| --- | --- | --- |
| 点结束 → 原工具可用、卡片出现待保存预览 | p95 ≤ 100 ms；不依赖后端响应 | 注入 2 秒写入延迟，仍能继续选文和滚动；记录事件至实际绘制时间 |
| 正常书写反馈 | 60 Hz 环境下 p95 ≤ 1 帧；笔画结束不引入 ≥ 50 ms 主线程长任务 | 输入轨迹与浏览器性能记录，覆盖笔画数量上限附近 |
| 点击已加载页的定位入口 → 目标可见 | p95 ≤ 200 ms；临时轮廓持续 1.8 秒 | 竖向、横向、旋转页及减少动态效果分别检查 |
| 冷页面定位 | 100 ms 内显示定位反馈；内容完成时间另测 | 连续点不同目标与加载中手动滚动，只允许最新有效请求改变位置 |
| 保存正确性 | 丢失响应、刷新失败、iframe 重建后不丢已确认暂存批次、不重复 PDF 笔迹 | 故障注入、原身份重试、导出后重新导入核验 |

笔迹写入与识别耗时分别报告分位数和失败率；它们不计入结束操作的响应预算。物理 Pencil、随航、iPadOS 27 和未来 Electron 仍需真实设备验收，浏览器合成事件不能替代手感测试。

## 分步实现与迁移

1. 先增加阶段计时并保留基线；交付卡片 SVG 预览、两个定位入口及临时聚焦，验证不会改变 PDF 内容。
2. 加入主机队列和恢复协议，测试有界接纳、不可变重试、跨窗口冲突、父批注删除及 iframe 销毁。旧 `reader:ink-draft` 按原 UUID、几何和 attempted 状态迁入；新记录确认成功后才清除旧记录，禁止双重消费。
3. 将“完成手写”实现为冻结并回到阅读；拆开当前全局输入锁与单论文写入队列，接入卡片状态及容量提示。自动保存使用同一冻结入口。
4. 将逐批整页刷新改为覆盖层与空闲合并刷新；再接入按已保存几何版本触发的识别，保留人工校对保护与已有请求重试规则。
5. 完成合成故障测试、键盘／窄屏检查及实际设备试用后，才更新已实现能力说明。

导入原件始终不改；管理副本继续使用标准 PDF `/Ink`、`/IRT` 及带来源标记的文字回复，写前备份并原子替换。目录不新增权威批注行，队列是可恢复的临时状态，PDF 仍是已保存批注来源。外部批注、原有自由手写与旧手写便签保持兼容。
