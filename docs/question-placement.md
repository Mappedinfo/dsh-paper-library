# 原生 PDF 问答放置计划与只读预检

## 放在哪里

默认一注一个原子主问题。先逐题找最相关、直接支持回答的局部原文，再确定批注位置；不按题号平均分配页数，不为视觉分散而强绑。来源、版本/子样本、数据对象或用途不同就拆分，尤其训练、选模验证、最终测试、校准、推断输入与参数来源不能混成一个数据用途。

每条保留独立的问题 ID、问题原文、答案、来源/版本/对象/用途、证据引用与放置理由。只有同一局部证据确实共同支持两题时，才允许同位置的独立问答；不将多题塞进一个长备注。答案需要其他页补充时保留那些页的逐条引用，主锚点仍须支持当前主问题。跨来源/版本的回答分成各自有来源的小项，综合说明另列。

缺失信息只说检查范围内未说明，不能推断全文不存在。无局部证据的全篇总结、导航、缺失结论标为 `context-not-evidence`（有导航位置但不是证据）或 `unanchored`（不绑定位置），明确理由与阅读范围；这些不计入有证据回答。不得用任意相关短语伪装证据。

锚点须是目标版本真实文字、1-based 物理 PDF 页码和逐行 quad。先确认文字出现次数，再校验 quad；换行产生多个 quad 不等于多次出现。重复短语不能把 `search_for` 返回的所有位置一起划线：扩大引文到唯一上下文后重检；仍不唯一则停止自动定位。不使用第一个命中、最长矩形或猜测页码。

## 可执行预检

新增独立、选择性调用的模块，不接管现有 PDF 写入接口，也不自动转换旧批次计划：

```sh
PYTHONPATH=src .venv/bin/python -m dsh_paper_library.placement_preflight plan.json sources.json
```

`sources.json` 是调用者明确提供的 `{"source-id": "/local/path.pdf"}`；PDF 路径不从 plan 推断。命令只读，JSON 报告写 stdout，失败退出码 1。计划格式：

```json
{
  "schema": "question-placement-v1",
  "questions": {"data.use": "这份数据用在哪一步？"},
  "entries": [{
    "id": "data.use.train",
    "question_id": "data.use",
    "question": "这份数据用在哪一步？",
    "answer": "供训练使用，具体说明待按原文填写。",
    "scope": {"source_id": "paper", "version": "v1", "entity": "dataset-name", "use": "train"},
    "status": "evidence",
    "anchor": {
      "source_id": "paper", "version": "v1", "sha256": "实际文件SHA256",
      "page": 3, "quote": "唯一、真实的完整原文",
      "quads": [[0, 0, 1, 0, 0, 1, 1, 1]]
    },
    "evidence": [],
    "review": {
      "reviewer": "审阅者或明确的审阅过程标识",
      "rationale": "为何这处直接支持本题，其他候选为何不合适",
      "most_relevant_local_evidence": true
    }
  }]
}
```

以上为字段模板，不是可通过样例；填入真实 hash/quote/quads，并将 anchor 对象完整放入 evidence 列表。每个 evidence 对象同格式。无锚点时 `anchor:null`；context/unanchored 另填 `reason`，明确检查范围与为何无局部证据。测试提供可运行的合成有效样例。

检查包括：题目 ID 与原文映射、逐题结果、独立条目、明确范围、来源版本一致、主锚点属于答案证据、非证据状态、人工/模型语义审阅记录、当前 PDF 哈希、真实物理页、唯一原文、实际 quad。仅进行 NFC/空白规范化，不做模糊匹配。报告逐题分别列 evidence/context/unanchored，不能以批注数或问题序号齐全代替覆盖。

预检不会自动判断答案是否蕴含于证据，审阅记录只是声明，不能证明真实语义正确；来源命名、版本和用途的意义仍由审阅者确认。没有自动语义打分或模型调用。结构通过不表示完成全部阅读、获得改写授权或现有批次已修复。当前没有强制接入运行中宿主或写入器，后续批量写入调用方必须显式使用它。

## 改写旧批注时的独立写入约束

预检不执行改写。若另行授权修复旧批次，调用方必须：

1. 精确列出目标批次和批注稳定 ID，以及每条旧内容/几何/回复快照。作者名、前缀或页码不能作为批量删除条件。不碰其他人工或外部批注。
2. 保存只读备份；在同一个受管文件写锁内重新读取文件哈希与目标快照。任意并发修改或原文变化时停止并重新规划，不覆盖他人更新。
3. 在临时副本修改，仅替换明确目标；保留原正文/页序、原有非目标批注、回复关系、链接、书签和其他 PDF 内容。验证新增问题与证据对应、目标完整替换、非目标快照不变；不以全文 text hash 单独证明其他 PDF 内容无损。
4. 序列化后重新打开并验证，成功后才原子替换；保留备份及批次回执。失败不改受管 PDF，不能先删后补。
5. 写入前在锁内再次核验版本；预检结果绑定完整文件 hash，不可用过期结果绕过并发保护。原件与实时 Zotero 数据库不改。

## 验证

```sh
.venv/bin/python -m pytest tests/test_placement_preflight.py -q
```

仅使用合成 PDF，覆盖重复短语多次出现、唯一引文跨行、错误页/版本/hash/quad、漏题、重复范围、非原子问题、未审阅、非证据状态和只读不变性。测试不声称真实论文语义已验收。
