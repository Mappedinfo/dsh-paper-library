Mermaid import/export passes **495 JavaScript / 220 Python tests** and the 30-check browser receipt. A pasted `flowchart`/`graph` is parsed into the whiteboard's own readable source document — never straight onto the canvas — so the existing 「校验并应用」 remains the only write path and the parsed result can be reviewed and edited first. The subset is exactly what the model can express: node shapes, `-->`/`---`/`-.->`/`==>`/`<-->`/`o--o` link styles, `-- text -->` and `-->|text|` labels, `&` groups, chained statements, `<br/>`, entities, quoted ids, `%%` comments and a `direction` override. Anything else is reported **with its line number** instead of guessed: `classDef`/`style`/`linkStyle`/`click` are ignored, `subgraph` is flattened, `~~~` is dropped, thick and circle-endpoint links are imported as approximations, identical links are merged, and the diagram's direction becomes the layout direction. There is deliberately **no mermaid dependency** — the package is a renderer plus dagre, and only a parser is needed. The browser receipt pastes a diagram, applies it, asserts the four nodes and four links in the host record and the left-to-right placement, then exports the canvas back to Mermaid text.

A line used to be clipped to the target's border along the centre-to-centre segment, so when the two nodes were nearly level — a wide, short paper node with a source just below its far corner — the arrowhead met the top edge at about 10° and read as a line lying along the node. Each end of a line is now placed so the drawn segment meets the side it lands on at the edge's **angle** (perpendicular by default, adjustable to 75/60/45/30, with a **30° floor** that clamps shallower requests), leaning with the centre line and stopping at a corner when the side runs out; the pair is settled over a few passes because sliding one end moves the line the other measures against. The property is measured rather than assumed: a deterministic sweep of 17,448 non-overlapping arrangements across the five settings keeps a worst incidence of 29.99° (coordinates round to 0.01 px), and the 29-check browser receipt measures the **drawn path** — the old geometry reports 10.4° there while the current one reports 90°. `angle` is an edge field: it rides in the board record and the readable source file (omitted when perpendicular) and the host validator accepts only integers from 30 to 90.

Dragging a node used to move its shape alone: `redrawGeometry` rewrote the shape's geometry while the node's `<text>` labels and its resize/connect handles kept their absolute coordinates, so the text only caught up on the next click, which triggered a full render. Each node now draws its children around its own origin and the whole node is positioned by a single `transform`, so a drag rewrites one attribute and the shape, the labels and the handles travel together (a resize rewrites only the local size and handle offsets). The 28-check browser receipt asserts the label moves with the drag itself — measured as `moved by 0,0` against the previous code — and that it does not jump again when the drag is released.

换行拼接修复通过 **478 JavaScript / 220 Python 测试**。取文此前在每个词之间都插入一个空格，因此跨行选择会多出一个空格（中文 PDF 尤其明显：一行常被抽取成一个“词”，于是每处换行都会凭空多一个空格，而行内本没有空格）。现在 `joinSelection` 按版面拼接：同一视觉行内的拉丁词保留空格，**换行处不插入分隔符**（因此 `measure-`+`ment` 仍是 `measure-ment`），中日韩字符相邻时一律不加空格；旋转页上按“同一行共享 left/right 或 top/bottom”判断行归属，横排与竖排都能正确分行。


选文精度修复通过 **477 JavaScript / 220 Python 测试**。根因是**隐形文字层与栅格文字不对齐**：每个词条按“词框高度的 85%”设置字号，实测渲染后的文字宽度比 PDF 词框宽出约 18–34 px，且词尾空格溢出到下一个词框之上——指针落在视觉可见的某个词上时，命中测试却落在相邻词的文字上（多选后“后面几个也被选了”），而按词框裁剪的旧逻辑又把这些词丢掉（“有些文字被跳过去了”）。现在每个词条内含一个 `inline-block` 文本 run，渲染后按 `scaleX(词框宽 / 实测文字宽)` 精确贴合词框；词间空隙与行尾由独立的空格 run 覆盖（行尾 run 宽度受控），因此把指针松开在词间或行尾时选区停在**前一个词**而不会被并进后一个词，也不会因命中裸图层而整段坍缩——`pointerup` 还会在浏览器已把拖选折叠时恢复本次拖拽最后一个真实 range。取文改为**按选区切片**：每个词用 Range 边界截出真正被选中的字符，横向取其自身矩形，纵向沿用词框，只要该词有选中文字就绝不丢弃；预览改成换行可滚动，完整显示多行选文。


AI 反馈写回修复通过 **465 JavaScript / 215 Python 测试**。此前一次针对多条批注的反馈会把整段回答写成一条 PDF 便笺，而界面把该便笺按 `annotation_ids` 挂在**每一条**来源批注下，于是同一段答案在所有批注里重复出现。现在 `feedback_context` 在多选时要求模型逐条回复（`mode:'per-annotation'`，严格 JSON），`save_feedback` 新增 `replies` 路径：一次原子写入中为每条批注写一条带 `/IRT` 的回复，且每条只引用自己的批注 id；未回答的批注记入 `missing`，绝不用别人的回答填充。模型若仍返回合并答案，则只保存一条（`combined:true` 并给出提示），不再复制。界面线程构建移入 `web/annotation-threads.js`：逐条回复只挂到自己的批注，历史合并反馈与主对话共享回复仍保留“涉及 N 条批注”标签但不会重复渲染跨批注文本。


精确选文修复通过 **456 JavaScript / 213 Python 测试**。PDF 连续阅读此前把选区吸附到整词框：`captureSelection` 直接用每个词的矩形与整词文本，因此从词中开始的一次拖选会得到整个词（在紧排的版面里看起来就像“从行首开始”）。现在 `clipWords` 用浏览器自己的选区矩形（`Range.getClientRects()`）逐词裁剪，并取每个词内真正被选中的文字片段（`selectedText` 用 Range 边界截取），只保留拖动覆盖的部分；同一行的相邻片段仍在 `mergeSelection` 里合并，跨列与跨行保持分离。11 项 `pdf-reader` 单元测试覆盖部分词裁剪、跨行覆盖不误剪、退化数据回退与空片段过滤，[24 流程阅读器回执](validation/reader-browser.json) 新增一项真实 Chromium 检查：从单词中部拖到另一个单词中部，阅读器捕获的文字与浏览器自身选区完全一致，保存的批注引用就是那段切片而不是整词或整行。

## Boundaries

Metadata/abstract retrieval only; no full-text index, OCR or resident embeddings. External (synced) sources are indexed from directory entries and filename evidence only: no PDF is opened, no content hash is computed, and a same-size/same-mtime rewrite is therefore undetected. One managed PDF per record. Metadata input is capped at 2,000 records / 32 MB, processed in batches of 100; larger exports must be split. PDF import is capped at 250 MB / 2,000 pages. Rendering is capped at 4 million pixels and 4,000 pixels per dimension. Annotation export is bounded and reports truncation. Native reference catalogs hold at most 1,000 user-note identities with 240-character text/comment previews. Exact selected sources plus temporary selection default to 24,000 Unicode characters; deployment configuration permits 1,000–96,000, with explicit rejection on overflow. Temporary selection separately allows 8,000 characters and the question 4,000. No automatic batch reading or model-memory guarantee is claimed.

Inline history contains at most 20 committed human/assistant messages, 6,000 characters per message and 48,000 total; full tool output, approvals, stop controls and older history are on the main page. Explicit reply-to-PDF saves require an attached PDF and a completed assistant event in the current history window, with at most 28,000 text characters. They preserve Session/message provenance and do not infer annotation associations. Archived Sessions remain preserved, with an explicit unavailable state because the current Harness public API has no unarchive method. Moving the library directory does not automatically migrate the Session correspondence.

Automatic parsing uses at most three pages / 30,000 characters; unreliable or incomplete fields remain flagged for review. Public acquisition covers Crossref/DOI, arXiv, direct PDFs and generic citation meta tags. Network branches beyond the W3C direct PDF are tested with deterministic transport fixtures. Authenticated publisher access, browser providers and live model generation are not validated here. The API documents all intake limits.

The continuous-reference update has automated, native Host, browser and scoped memory evidence. The updated local deployment and refreshed native library pane are verified in the [installation receipt](validation/annotation-reference-install.json). Actual-library migration and reading tests were not performed. Public source publication uses the MIT license for original project files, preserving third-party terms and excluding runtime data.
