# 持续批注与对话引用

2026-09-14 · 当前源码已实现，151 项 JavaScript、48 项 Python、隔离 Harness 的 13 项原生检查和 11 项浏览器交互检查通过。本文记录接受后的交互、来源与持久化约定。合成 2,000 条记录／1,000 个 PDF 的内存检查已完成，浏览器另有四个阶段的采样；现有安装已升级并重启，原生应用已刷新，批注引用能力和文献库面板均已验证。证据范围见[验证记录](validation.md)。

官方接口审查基线为 DeepSeek Harness `c291e7961a515f6d7af9304e7fd1d257929aef26`。这些接口仍处于 pre-stable 阶段；插件没有修改 Harness 源码。

## 本次引用的批注集合

读者可以持续保存批注，再选择其中几条提问、组合新旧批注，或引用当前文章的全部用户批注。插件内对话与 DSH 主对话使用同一篇论文的会话、模型和历史。

```text
本次引用  [批注 3 条 ＋ 第 5 页选文 · 查看/调整 ×]
添加批注  [新增与更新 4] [选择…] [全部 23]
────────────────────────────────────────────
这几个批注之间有矛盾吗？
                      [发送] [放入主输入框 ↗]
```

三个入口向同一个集合添加材料，按批注 ID 去重。单条批注的“加入本次引用”可撤销，不覆盖其他选择。临时 PDF 选文与保存的批注可以共存，选文有独立标签和移除操作。没有选择批注时可以普通追问，不默认重发所有批注或论文全文。

| 入口 | 当前行为 |
|---|---|
| 新增与更新 N | 添加尚未发送的当前版本，展开待发送列表，可取消其中几条 |
| 选择… | 打开可检索、按页筛选的多选抽屉；可查看待发送、全部或本次已选 |
| 全部 N | 添加点击时当前文章的全部用户批注，排除 AI 回复；目录未完整读取或存在重复身份时不可使用 |
| 查看/调整 | 核对本次集合，移除条目，或显式采用已编辑批注的当前版本 |

抽屉每页显示 20 条，筛选和翻页保留勾选。目录最多保留 1,000 条轻量条目，原文与评论各预览 240 字符；这是列表预览，发送前会重新读取所选版本的完整正文。保存新批注后显示“又新增或更新 N 条”，当前集合保持不变，用户点击“加入”才会改变它。

问题、引用身份、选文和未确定结果的发送记录按论文保存到 DSH 本机状态文件，每条记录上限 256 KiB。不同浏览器连接同一服务时共享这些草稿；内存工作集受限，旧草稿不会因最近使用顺序而被删除。超限、写入失败和跨窗口修改冲突均明确提示，并保留未保存内容供恢复。跨侧栏重挂载的临时阅读状态另有 256 KiB 上限，包含当前论文、页码和草稿，不保留 PDF 图片；已保存的本机草稿优先于旧的临时快照。该存储约定于 2026-09-15 更新，详见[语言与本机存储](ui-review-design.md)。

## 版本与发送状态

“新增与更新”相对于这篇论文会话已持久记录的批注版本。保存、选择、准备引用和放入主输入框均不推进发送基线。原生队列接收只表示排队成功，回复是否完成单独显示。

批注版本使用页码、类型、规范化原文、评论与位置的 SHA-256。换行和 Unicode 形式会规范化，坐标取千分之一 PDF 点；PDF 文件哈希、修改日期和无关 AI 回复不会把所有旧批注都变成更新。

- 未发送过的身份显示“未发送”。
- 当前版本与已记录版本相同，显示“已发送”。
- 同一身份内容已改变，显示“发送后已更新”。
- 草稿引用版本过期时要求核对并采用当前版本；已删除条目要求移除。不会静默更换材料。
- PDF `/NM` 缺失时使用页码与 xref 回退，界面提醒外部阅读器重写后可能需要重新选择。重复 `/NM` 的批注不能可靠引用，必须修复或排除。

第一次准备发送会将完整材料和问题冻结为私有快照。逻辑提交保留快照 ID 和请求 ID；失败结果不明时重试这份快照，不重新解析变化后的 PDF。用户修改问题或引用后，会发起新的逻辑提交。已冻结的历史材料继续保留当时版本。

发送基线由 Harness 的 `paperLibraryAnnotationUsage` 日志投影产生。仅接受 `user/message` 中由 `Paper Library` 写入的来源元数据，同时核对当前会话和实际正文哈希。用户消息里的 token、队列状态或 AI 文本不能单独证明批注已发送。读取状态时，已激活会话还需通过 Harness 的持久化 flush 确认。

投影最多保留 5,000 个批注身份的最近发送版本，超过后按最近引用顺序释放，返回 `usage_truncated:true`。被释放的身份不能再据此断言从未发送；它可能重新成为待发送项。这个使用记录可从原生日志重建，PDF 仍保存权威批注。

## 覆盖范围与长材料

发送时完整核对选定的 ID、版本和正文，不沿用列表里的 240 字符摘要。默认预算为用户批注原文、评论与临时选文合计 24,000 个 Unicode 字符。部署配置 `maxAnnotationCharacters` 可设为 1,000–96,000；浏览器不能自行覆盖它。选文另限 8,000 字符，问题限 4,000 字符。

超过预算会拒绝准备或发送，要求减少选择、分次提问，不自动截断。一次模型步最多解析 4 组快照，并对其中来源文本执行合计预算。超过 1,000 条目录条目或有界扫描未完成时明确报告目录不完整，“全部”不会把已载入部分冒充全量。

当前没有自动分批阅读、全量合并总结或长期模型记忆保证。读者可以手动缩小集合，后续再次选择旧批注进行比较。主对话压缩后模型未必仍能看到早期材料；“已发送”只是使用记录。历史引用卡片可查看当时快照，当前版本仍需从批注列表重新选择。

## 官方引用接口与实际呈现

插件通过 `ctx.inputTriggers.registerSource()` 注册 `paper-library-annotations`，用 `slash/input-insert-reference` 插入一个集合标签。插入采用目标会话的 scoped Context、TokenSpan 和 draft revision，保留已有文字、文件引用及附件。原生标签不需要伪装成文件或会话图标。

引用身份使用以下稳定 token，`paperId` 和 SHA-256 仅由配置文献库中的快照解析。

```text
[[paper-library-ref:v1:<paperId>:<snapshotId>]]
```

标签的 `clipboardText` 与 `codec.serialize()` 都使用同一个 token。Harness 刷新后恢复普通字符串，插件显示“查看引用”入口；目前不承诺自动重建原生标签。普通 token 仍可由 Host 解析，不能依赖浏览器当时打开的论文决定材料。

Host 在公开 `agent/pre-step` 扩展点等待 `next()`，只处理用户明确提交的 token。它读取不可变快照，核对文献库、文献、会话和预算，将用户消息中的 token 转成可读标签，并追加一条含完整来源正文的原生用户角色上下文。来源元数据保存在日志字段中。

```text
source.kind = plugin
source.plugin = Paper Library
source.paperLibraryReference = { version, paperId, sessionId,
  snapshot_id, annotation_refs, body_hash }
```

版本哈希和快照身份保存在来源字段，正文保留读者需要核对的批注 ID 与页码。模型可见正文可从原生日志复原，投影据此核对发送版本。

点击输入标签会按需打开快照检查器，并可返回 PDF 页码。检查器使用官方可追加的 `conversation.input.dock`，当前只保留一份预览。插件历史有可展开的当次引用卡片；DSH 主历史使用官方通用 `Paper Library` 上下文显示，展开后可读实际正文和来源字段。没有替换主消息渲染器，也没有占用会与其他插件竞争的消息尾部链。

官方来源包括[文件引用](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/context/file-reference/README.md)、[会话引用](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/context/session-reference/README.md)、[自定义 source/codec](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/ui-input-trigger/src/types.ts)和[输入插入约定](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/ui-conversation/src/client/contract/input.ts)。官方文件引用只传路径，不会自动读取 PDF 批注。

## 数据与资源归属

标准 PDF 对象保存可编辑的权威批注；文献库内 `.paper-library/snapshots/` 保存按内容寻址的不可变引用，`.paper-library/requests/` 保存逻辑请求绑定。目录使用 `0700`，文件使用 `0600`；原子发布不会覆盖已有快照。快照记录最多 1 MiB，格式化正文最多 200 KiB。损坏、丢失、身份不符或路径越界的快照会拒绝读取。

快照和使用投影不是第二份可编辑批注数据库。当前论文打开、保存或明确刷新时才运行短时 PDF 解析；没有全库监听、后台嵌入或常驻 PDF 引擎。浏览器历史仍限 20 条、每条 6,000 字符、合计 48,000 字符。

自动保存后发送默认关闭。显式开启后，每次保存的新批注可以提交到该论文会话并使用模型额度；正在发送时的新保存会提示尚未发送，不会静默丢失或暗中追加。模型选择、工具权限、停止和 Agent 生命周期继续由这篇论文的 Harness 主对话管理。

实现入口为 `web/paper-chat.js`、`src/client/annotation-references.mjs`、`src/harness/annotation-snapshots.mjs`、`src/harness/paper-reference-resolver.mjs` 和 `src/harness/annotation-usage.mjs`。操作字段见 [API](api.md)，当前验证状态见[验证记录](validation.md)。
