# 持续批注与对话引用设计

2026-09-14 · **设计提案，尚未实现**。本轮只分析交互与官方接口；现有安装和运行时代码不变。

审查基线：Paper Library `e56944e666cbb4351827f883c8fc7e915483f411`；DeepSeek Harness `c291e7961a515f6d7af9304e7fd1d257929aef26`。下文源码行号针对这两个版本。官方接口仍处于 pre-stable 阶段。

## 用户任务与核心对象

读者持续阅读同一篇论文，保存批注，偶尔只问新批注中的几条，偶尔组合新旧批注比较，也可能要求通览所有批注。论文对应一个 DSH 会话，插件对话和主对话沿用这个会话的模型与历史。

核心对象是 **本次引用的批注集合**。新增与更新、手选、全部是生成集合的快捷操作，不是三个聊天模式。用户选择材料和编写问题是两个独立动作；选择本身不调用模型。

## 紧凑布局

```text
本次引用  [批注 3 条 · 查看/调整 ×]
添加批注  [新增与更新 4] [选择…] [全部 23]
────────────────────────────────────────────
这几个批注之间有矛盾吗？
                      [发送] [放入主输入框 ↗]
```

输入框常驻一个集合标签，避免 100 条批注占满编辑区。点击标签展开页码、原文摘要、评论和移除操作。窄面板将添加入口折叠进一个菜单，当前已选数量始终可见。没有已选批注时保留普通追问，不默认重发全文或所有批注。

「选择…」打开局部抽屉：支持文本检索、页码筛选、多选；可切换待发送、全部、已选列表。筛选和分页不清除勾选。每条批注旁提供「加入本次引用」，可撤销，既不覆盖其他选择，也不强制跳离阅读。PDF 临时选文可以和已保存批注共存，但明确标作“选文”，不伪装成持久批注。

| 入口 | 范围 | 用户控制 |
|---|---|---|
| 新增与更新 N | 当前论文会话尚未发送的批注版本 | 展开后可只选其中几条，也可与旧批注组合 |
| 选择… | 当前论文的用户批注 | 勾选、搜索、取消；保留本篇草稿选择 |
| 全部 N | 点击时当前论文全部用户批注 | 排除 AI 回复；显示实际数量和长度，超预算时先处理范围 |

快捷操作把条目加入同一个集合，按身份去重。之后统一显示“已选 N 条”，不保留会误导用户的动态“全部模式”。集合创建后再保存批注，显示“又新增 2 条 · 加入”，不自动改变已选集合。手动编辑过的问题和选择应按论文保存，切文章后可恢复。

## 新增、编辑和发送的语义

“新增与更新”相对于 **这篇论文会话已成功记录的引用版本**，不是最近打开时间、最近保存时间或最近一条 AI 回复时间。第一次讨论时，已有用户批注都属于尚未发送，可继续筛选。界面使用“未发送 / 发送后已更新 / 已发送”，不使用无法验证的“AI 已理解”或“已解决”。

- 保存只负责写入 PDF 并刷新待发送计数；自动 AI 请求保留为显式可选设置，默认关闭。连续保存不应制造多轮自动回复。
- 加入本次引用、打开主对话、放入主输入框均不推进发送基线。只有能从原生会话日志确认这份引用快照的身份和实际正文已持久记录，才记作已发送；队列接收或 HTTP 返回本身不足以证明这一点。若 Host 在 pre-step 注入来源上下文，还需对账对应日志，不能只看到用户消息里的引用 token 就标记成功。
- 同一批注修改了有效内容，就成为更新。建议使用稳定 ID 加规范化原文、评论、页码和位置的内容 hash；单独依赖 PDF 文件 hash 会将无关新增和保存 AI 回复误判为所有批注都更新。外部修改时间可能缺失，不作为唯一依据。
- 发送前核对选定版本。草稿期间被编辑的条目标记“内容已更新”，允许查看并采用新版本；已删除的条目提示移除或明确使用历史快照。避免悄悄更换问题依据。
- 每次逻辑提交冻结批注 ID、版本、实际文本、位置和 request ID。结果不明时用同一快照重试；用户改了问题或引用版本，就创建新的逻辑提交。不能以相同 request ID 重新读取变化后的 PDF 内容。
- 已发送后又新增或编辑，只影响下一轮；旧会话消息保留当时快照。已发送与回复完成分开显示，失败时保留问题和待发材料。

外部 PDF 批注缺少稳定 `/NM` 时，当前实现用页码和 xref 回退；外部阅读器重写 PDF 可能改变身份。将无法可靠匹配的条目标作待核对，不宣称跨任意阅读器重写都能无误追踪。

## “全部”与模型上下文

“全部批注”不等于论文全文，也不等于 AI 回复。当前 UI 在 `web/paper-chat.js:174` 只取前 40 条；`core.py:1007` 又限制每条原文/评论各 1,500 字符、总量 12,000 字符。聊天 UI 没有充分呈现截断和遗漏。下一版首先应消除这种覆盖范围歧义。

实际发送前显示 N/N 条以及文本长度。正文超预算时，让用户缩小选择，或明确进入分批阅读。按需读取可以作为长材料路径，但必须有可用工具、稳定条目索引和覆盖记录；不能只发送文件名就称全部内容已送达，也不能仅放宽 40 条上限而移除内存与上下文预算。

曾发送仅是使用记录。长会话压缩后模型未必仍能看到原文，因此保留按批注 ID 重新引用/读取的入口；涉及新旧批注对照时，允许主动携带旧批注。历史引用保留当时版本，读当前版本时明确其变化。

## DSH 官方能力与适配边界

以下链接固定到本轮审查的官方提交；公开原始文件也已通过网络读取确认。

| 官方能力 | 已有实现 | 本插件还需负责 |
|---|---|---|
| 文件/文件夹引用 | `@path`、带空格的引号路径、输入框原生引用标签 | 路径引用不自动读取/附加内容；PDF 批注解析不能省略 |
| 对话引用 | `@[label](dsh-session:…)`；Host 在 `agent/pre-step` 准备有界文本快照 | 不是 PDF 批注；不支持指定单条消息或消息区间；拒绝引用自身 |
| 自定义输入引用 | `InputTriggerSource`、`ReferenceCodec`、程序化插入事件 | 批注候选、身份、文本解析、位置跳转、草稿恢复与来源记录 |
| 文件行号导航 | 侧栏预览可带 `line` 参数 | 只是导航，不是模型的行区间引用；未发现内置 PDF 页码/矩形/批注引用类型 |

官方来源：[文件引用说明](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/context/file-reference/README.md)、[对话引用说明](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/context/session-reference/README.md)、[自定义 source/codec](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/ui-input-trigger/src/types.ts)、[侧栏预览](https://github.com/deepseek-ai/deepseek-harness/blob/c291e7961a515f6d7af9304e7fd1d257929aef26/packages/client/ui-sidebar-documentpreview/README.md)。

建议通过 `ctx.inputTriggers.registerSource()` 注册批注来源；用 `slash/input-insert-reference` 向目标会话添加一个集合标签。`codec.serialize()` 可异步取得本次真实内容，解析失败会阻止发送；`openReference()` 可由插件处理点击、打开论文对应页码，并返回是否接管该动作。插入走原生 span/revision 检查，保留原有文字、引用和附件。标签的 `appearance` 目前仅 file/folder/session，可省略，不假设已有批注专用图标。

注册 source 不能独自完成全链路：

1. **草稿恢复**：官方持久化保存字符串，标签退为 `clipboardText`；重挂载时恢复普通文本。自定义批注引用需要可持久识别的 token 和 Host 解析，或可靠的标签重建路径。身份不能依赖浏览器当前打开的论文。只有浏览器内存中的 codec 不足以支持重启后发送。
2. **已发送消息展示**：`ui-primitives/src/user-text.tsx` 当前专门识别 file/session/skill/command，并未自动调用任意 source 的消息渲染器。优先保证主对话能看到带页码、ID 的真实可读文本；紧凑、可展开、可回跳的历史引用卡片要单独验证适用的公开 slot/view 扩展。不要把未验证的历史卡片效果写成官方现成功能。
3. **两处输入**：插件与主对话共用引用快照和发送协议；转交草稿时使用同一个集合身份，不能在两边各自重新挑选“最新批注”。主输入框实际发送后，插件通过原生日志对账，不能只依靠插件自己的发送按钮更新状态。

源码依据：`ui-conversation/src/client/contract/input.ts:62`（插入契约）、`input/facade.ts:268`（字符串草稿恢复）、`:491`（版本检查）、`:735`（发送序列化）；`ui-conversation/tests/input-reference-submit.client.spec.ts:35`（刷新引用测试）；`ui-primitives/src/user-text.tsx:1`（发送后展示）。上述路径均位于官方 `packages/client/` 下。

## 内存与数据归属

PDF 继续保存权威批注；DSH 日志保存当次实际引用内容。发送状态只是可从日志重建的轻量使用记录，不是另一份可编辑批注数据库。当前论文打开、保存或明确刷新时按需读取；筛选和检索结果分页，不常驻监控或解析全部 1,000 个 PDF。

集合携带条目身份和版本，正文仅在预览/发送时有界加载。只在当前论文维护必要状态，失活时释放缓存；稳定快照需要落盘并记录日志来源，不能靠永不释放的内存保持引用可用。任何新解析器都应检查会话对应的文献范围，不能把可手写 token 当任意文件访问授权。

## 建议的实现顺序与验收

1. 修正“全部”的覆盖提示，增加多选集合、保留草稿和明确待发送状态。验收：连续保存五条只选两条，随后再加一条，原选择不变；新旧混选、全部和普通无引用追问均可完成。
2. 引入冻结快照和日志对账。验收：编辑旧批注、删除待发项、发送失败重试、回复失败、从主对话发送，都不会丢失材料或错误推进基线。
3. 接入官方输入引用标签。验收：已有 DSH 草稿/附件/标签保留；刷新、重启、切文章和两处输入得到相同内容与来源；失效引用显式报错。
4. 验证历史卡片与长材料按需读取。验收：超过 40 条与超过文本预算时不隐瞒遗漏；压缩后可重引旧批注；小窗口可操作。用合成文献测量浏览器、Host 与短时 PDF worker，单独报告峰值和闲置内存。
