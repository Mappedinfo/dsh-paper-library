# 外部文献源：把数据同步服务同步来的论文纳入同一个地址

Paper Library 和数据同步服务**并列存在、可以各自独立安装**。没有任何一方依赖另一方：
论文仓库不安装、不调用、不读取同步服务的密钥，同步服务也只把文献库目录当成普通备份源之一。
两边通过一件事相连：论文仓库可以**按符号链接索引**同步服务已经维护好的 PDF 目录，
从而得到一个统一的论文访问地址，而不复制、不移动、不删除任何原文件。

## 配置

两条路都可用，都不配置时插件行为与从前完全一致。

**部署配置**（`cordis.patch.yml`，可用环境变量）：

| 键 | 环境变量 | 说明 |
| --- | --- | --- |
| `externalSources` | `DSH_PAPER_LIBRARY_SOURCES` | 数组或 JSON 数组文本：`[{"id":"archive","root":"/绝对/路径"}]`，最多 8 个 |
| `syncConfig` | `DSH_PAPER_LIBRARY_SYNC_CONFIG` | 另一个同步服务自己的 JSON 配置文件的绝对路径；插件只读其中的目录列表 |

**运行时设置**（插件设置卡 / DSH 设置 → 插件 → Paper Library）：

- `数据同步服务配置（可选）`：同步服务配置文件路径，填写后立即生效，留空表示不启用。
- `额外外部文献源`：JSON 数组文本，例如 `[{"id":"archive","root":"/Volumes/archive/papers"}]`。

设置里的值优先于部署配置，部署配置作为兜底，因此两条路可以同时存在。
`syncConfig` 指向的文件会按 mtime 缓存，改完不必重启；文件缺失、改格式或不可读时只报告原因，
不会让插件失效。

以 Vault Sync 为例，它自己的配置里已经列了每个同步源：

```jsonc
{ "sources": [ { "id": "zotero-attachments", "kind": "directory", "root": "/绝对/路径" } ] }
```

插件只取 `kind == "directory"` 的目录项（跳过它自己的 `paper-library` 源），
按 `sync-<id>` 命名接入。

## 扫描与索引

工具 `library_sources` 只读状态；`library_sources_scan` 支持 `scan` 与 `prune`。
每次调用默认最多索引 200 个新文件（上限 2000），剩下的记为 `pending`，
再调一次即可续跑，因此几千篇文献可以分批完成，单次调用始终有界。

一次扫描只做三件事：

1. 遍历目录、读文件大小与 mtime；**不打开 PDF、不算哈希**，所以 4.6 GB 的目录也不会读满盘。
2. 对新增/变化的文件建一条目录记录（`papers`），元数据只来自**文件名**：
   `作者 - 年份 - 标题.pdf`、`年份 - 标题.pdf` 或纯标题，写进
   `parse.field_sources = synced-filename`、`parse.needs_review = true`，并打上「外部同步」标签。
   没有证据的字段（作者、年份、DOI、期刊）一律不猜、不填。
3. 在 `<书库>/external/<source>/<相对路径>` 建一个**符号链接**。

未变化的文件由 `external_files` 里的 size/mtime 记录直接跳过，所以第二次扫描是
「遍历 + 查表」而不是重新索引。实测：425 个 PDF（约 4.6 GB）首次扫描 0.2 秒量级，
增量重扫 0.1 秒量级，目录文件约 2 MB；上限与样例都是本机实测/代码预算，不是更大规模的估计。

## 单一访问地址

`<书库>/external/` 就是那个虚拟文件夹：

```
~/.local/share/dsh-paper-library/
├── catalog.sqlite3              目录：题录、图谱、草稿、FTS 索引
├── pdfs/                        受管副本（导入的、以及写过的同步论文）
├── external/
│   ├── README.md                自动生成的说明
│   ├── zotero-attachments/…     → 同步服务维护的原文件（符号链接）
│   └── cloudsync-academic/…     → 同步服务维护的原文件（符号链接）
└── backups/
```

阅读器、批注、自动整理和文件管理器读的都是同一个地址。
同步服务里的原文件仍然在原处，论文仓库只是多了一个入口。

## 写入策略：先复制，再修改

同步目录是**只读**的。第一次给同步论文写批注、改资料或写回 AI 回复时，插件先把该 PDF
复制到 `pdfs/`（原子替换、0755→0600 权限、校验 `%PDF-` 头），把目录记录的 `pdf_path`
改指向副本，然后才写入。因此：

- 同步服务「从不写入源目录」的承诺不被破坏，实测源文件字节不变；
- 论文仓库「不修改导入原件」的承诺同样成立；
- 没有批注的论文永远不会被复制，上千个 PDF 不会变成两份。

已复制（promoted）的记录在后续扫描中保持受管副本，不会被降级回符号链接；
链接会在下次扫描时重新补上，访问地址始终完整。

## 文件消失、改名与清理

- **消失**：记录与它的批注、图谱、笔记都保留，只把符号链接删掉、把
  `external_source.missing` 标为 `true`；文件回来后再次扫描即恢复。
- **改名**：同一目录、同一大小、唯一候选时按重命名处理，沿用原记录（不产生重复论文）。
- **`prune`**：只删除已经失效的链接，不删除任何目录记录。
- 库外路径永远无法进入索引：源根目录不能位于书库内部，符号链接目标也不会被跟随写入。

## 与备份/同步服务的边界

同步服务扫描目录时默认**不跟随符号链接**（Vault Sync 的
`tests/symlinks.test.mjs` 固定了这一点），所以 `external/` 里的链接不会被当成独立文件
重复上传；这些 PDF 在同步服务自己的目录源里已经有一份，各按各的路径备份一次。

需要在同步服务里排除 `external/**` 时也可以显式排除，但通常不必：
`external/` 里只有链接，没有内容。

## 限制

- 索引不解析 PDF 内容，所以没有 DOI、摘要、期刊、页码；这些仍由既有的「补全资料」
  或自动整理按需补齐，补齐后的字段来源会单独记录。
- 文件名可能不含作者或年份（例如 `0112110v1.pdf`），这类记录的元数据就是文件名本身，
  保持 `needs_review`，不会被编造。
- 内容修改但大小与 mtime 都不变的文件不会被发现（没有哈希，这是性能上的取舍）。
- 源目录改名或移动会让旧记录标记为 `missing`，需要用新的根目录重新扫描。
