# LaTeX 单人自审

在现有 LaTeX 工作台形成「定位 → 记录疑问 → 改稿 → 复查」的个人流程。
人工批注、定位和导出不调用模型；明确点击「问 DSH」或「生成修改提案」时使用所选宿主模型。

## 使用

1. 保存源码后，在工作台编译一次。预览工具栏显示「SyncTeX 已核验」后，双击 PDF 正文可定位到真实输入文件的源码行。光标旁的原有正向定位按钮也使用同一份 SyncTeX。
2. 选中源码，点「批注选段／当前行」；没有选区时记录光标所在行。写下疑问、推理或修改想法，点「保存批注」。
3. PDF 可上下连续滚动全篇，当前页随位置更新，只渲染当前位置及相邻页。选择「高亮」「下划线」「删除线」后在单页内选文，标记直接保存，无需填写评论；选择「批注」后选文可直接写文字。用「区域」框选图表／版面位置可写便笺。扫描页使用区域便笺。保存失败保留选段与草稿供重试。
4. 顶栏「批注与写作」打开阅读侧栏：上方维护人工源码／PDF 批注，下方使用 DSH 提问、查看协作记录与审阅修改提案。长列表和协作区分别滚动，人工记录与模型输出保留各自来源。可按待处理、全部、已解决、待重定位、源码、PDF 筛选；点击有效位置返回原选段，编辑想法、解决或重新打开。
5. 每条批注都有「编辑／解决（或重新打开）／问 DSH／生成修改提案」。DSH 使用这条已保存批注的原文、评论和版本；回复与提案显示在对应卡片下，人工评论保持原样。旧版本回复会单独标明。源码批注针对所属文件；PDF 批注以当前打开源码为明确目标，旧 PDF 锚点只作参考，不猜源码位置。提案确认后才写入，不自动解决批注。
6. 底部输入可点「添加批注」，绑定当前已保存源码的选段或当前行；失败保留文字。右上齿轮「设置」选择 DSH 写作模型，翻译模型仍单独设置。
7. 从侧栏导出有轮廓的 JSON、笔记 Markdown 或批注 PDF 按钮。PDF 导出包含当前编译版本的原生批注，并附入全部自审记录 JSON（含源码批注和旧编译锚点）。源码批注作为附件保存，不伪装成 PDF 页面的准确位置。

协作日志沿用最近4条的有界记录；批注保存内容不会因此删除。未保存的源码不能建立源码批注或进行精确逆向定位。PDF 批注属于当前显示的已编译版本；源码有未保存改动时明确提醒。批注草稿未保存时，切换项目／主入口、编译和关闭会被阻止，内容留在编辑框内。保存失败和版本冲突也保留批注文字及原选段，重试新建请求沿用同一标识，避免重复记录。

「问 DSH」和「生成修改提案」默认可检索当前项目。它能查找其他已保存章节，按行读取源码、书目和说明，也能按页读取项目内已有文字层的 PDF。查到的片段交给当前选定的 DSH 模型；源码、PDF 和人工批注保持原样。项目之外的文件不会加入检索范围。如果共享章节在登记目录之外，可通过项目位置设置登记共同目录，再选原来的主 `.tex`。

需要核对公开文献时，打开齿轮「设置 → 本次检索」，为下一次提问或提案启用公开学术检索，填写最多 3 行公开关键词。只有这些词用于 Crossref 和 arXiv 请求；稿件、问题和批注不会自动变成公开查询。关键词仅用于下一次请求，使用后清空。回复、提案和对应批注的「检索来源」可查看文件行号、PDF 页码、题录或摘要链接及未查、无结果、不可用等状态；有限结果不能证明学界共识。「停止」结束当前生成，提案仍须明确接受才会写入。

## 精确定位与版本

定位调用本机 `synctex edit/view`，使用 PDF 点坐标；预览显示宽度、DPR、缩放和当前页只决定坐标换算，不进行关键词猜测。
工作台编译使用 `latexmk -g … -synctex=1`，强制本次生成输出，避免把外部替换的 PDF 当成缓存编译成果。
编译记录保存当前主入口、PDF／SyncTeX SHA-256，以及实际 SyncTeX Input 项目源文件和静态书目路径的内容指纹，并核对编译前后的源文件快照。
缺少数据、外部编译未核验、源码改变、SyncTeX 改变、读取或预算失败时禁用精确定位并给出原因。
必须保存并在工作台重新编译以恢复核验；不自动触发编译来覆盖用户现有产物。

源码批注锚定文件、内容修订、Unicode 码点选区和原文；PDF 批注锚定主入口、编译 PDF 哈希、页码和矩形，同时记录当时来源修订。
不同主入口的列表独立。源码改变或 PDF 编译改变后，会在同一源码文件或当前 PDF 中自动查找原引用。唯一的原文或仅空白／Unicode规范形式变化的匹配可恢复定位；引用足够长时，轻微改字、增删的匹配率至少96%，且不存在90%以上的另一处近似候选时，也可自动定位。短文本、多个候选、缺少引用文字的区域便笺及超出扫描／计算预算的内容仍保留「待重定位」，不挑最近一处。

自动匹配明确标记分数与方式，保留可展开的原始位置。它是当前视图的只读定位结果：原批注ID、版本、评论、状态与原始锚点不变，不会自动将批注标为已解决或修改原稿。PDF可跨页匹配，点击跳转开头，各页以虚线投影显示；显示坐标已转换的旋转页可定位，未核验的SyncTeX仍保持原保护。

JSON导出包含匹配结果，Markdown同时列出原始位置与匹配位置。下载的标准PDF批注仍属于原编译版本；自动匹配投影没有被写作新的原生PDF批注。原PDF证据及历史版本保持原样。

## 复用与存储

- 复用 `PaperReadingPanels` 阅读侧栏、`PaperPDFReader.mergeSelection` 选区合并，以及 Library 的 `_add_annotation`、`_annotation` 和备份／校验／原子替换管线。
- PDF 批注写入资料库私有目录 `latex-review/<project-id>/<main-path-hash>/<original-pdf-sha>.pdf` 的审阅副本。原始编译 PDF 不写入；既有外部批注保留。每条自审元数据随标准 PDF 对象保存，读取无需目录中的批注表。
- 源码批注在同一入口目录的 `source.json`，写前保留 `source.json.bak`，原子替换。每条笔记使用内容版本进行 CAS，旧版本写入返回冲突。
- `build.json` 仅保存映射核验指纹。目录拒绝符号链接，源码锚点仍经过项目边界检查。
- 自动匹配只在读取批注时有界执行，PDF完整范围最多80页、120,000词、1,000,000字符；单条引用最多20,000字符，模糊匹配最多2,048字符，整次列表有总量与候选／比较预算。未扫描完整范围时不会声称唯一。源码不跨文件寻找，迁移自其他入口的旧PDF记录不自动关联到当前入口。
- 一次最多显示／维护 300 条批注；每入口最多 12 个审阅 PDF、合计 250 MiB；源码 JSON ≤2 MiB、单条想法 ≤8,000 字符、选段 ≤20,000 字符。达到预算明确拒绝，先导出再整理，不自动删除历史。
- PDF 每次仅渲染当前页，沿用现有精确密度和资源安全边界；词层最多 20,000 词，PDF 对象预览最多 300 条。没有后台全库解析或常驻 PDF 引擎。

API：`latex_review_list`、`latex_review_put`、`latex_review_export`、`latex_review_delete`；详见 [API](api.md#latex-projects)。显式删除仅接收当前入口的自审 ID 和版本，保留备份，不删除外部批注。

## 手动编译版本与阅读项目

工作台每次成功手动编译会保存一条不可变版本：本次 PDF、项目文本源码、自审记录及其原有原生批注 PDF 副本。自动编译不创建版本；编译失败不冒充有效版本，版本复制失败会单独提示，原资料保留。

「版本」页和导航中当前写作项目的「编译版本」按钮读取同一条记录。可在工作台内预览本次 PDF、查看带原生批注的旧编译 PDF、读取源文件快照和自审内容，也可下载 PDF。「下载带有批注的 PDF」保留该版本保存时当前 PDF 上的原生批注，并附入该版本全部自审记录 JSON；源码批注与旧编译锚点保存在附件，不会被贴到当前页面。版本保存后的新批注不属于这个不可变快照。历史版只读，不使用当前稿的 SyncTeX 或写批注。

项目菜单可关联已有阅读项目；未关联时，首次保存版本建立同名阅读项目，不按名称猜测合并。更换关联后，已有版本 ID 和快照内容保持不变，转入新阅读项目；解除关联保留原有版本归属。

旧批注始终保留所属编译哈希、页码与原锚点；新版排版变化后不会自动把旧坐标贴到新页。一次版本最多保存 300 个文本文件，单文件 1 MiB、合计 16 MiB，自审副本遵守 250 MiB 预算；超过预算明确提示未保存版本，不产生不完整记录。版本保存在私有资料库的 `latex-versions/`，原稿与编译输出留在原处。

## 验证

[本轮验证回执](validation/latex-review.json) 记录自动检查和现有工作台的实际验收范围。
可重复合成稿：`PYTHONPATH=src .venv/bin/python scripts/latex-review-fixture.py`。
脚本只在临时目录生成主稿／草稿与独立测试库；打印路径后在现有工作台登记并编译一次。
测试笔记使用「合成验收：」前缀，清理必须核对项目 ID、目录标记及笔记版本，不能清理真实项目。
