# Operation contract

Node `dispatch(request, options)` accepts JSON `{action,...arguments}`. Python worker receives one JSON request on stdin and emits `{ok:true,result}` or `{ok:false,error}`. Core receives `library` absolute directory from adapter, never browser payload. Node unwraps result and throws on failure. Browser POST `./api` receives the same envelope. All pages are ONE-BASED; rects are PDF points in page response coordinates.

Core actions:

- `status` → `{count,archived_count,total_count,library,...}`; `count` excludes trash. The HTTP carrier adds `paper_conversations:boolean`, `annotation_references:boolean`, `catalog_management:true`, `typed_graph:true`, `reading_workspace:true`, `durable_state:true`, `learning_records:true` and `language_learning:boolean` (generation availability).
- `import` with `path` (PDF/directory/JSON/RIS/BIB) or `items` (CSL array), `limit=100,offset=0` → `{imported,duplicates,skipped?,items:[item],warnings:[],next_offset?,done?,total_records?,total_files?}`; Node resolves DOI and BibTeX before core. Repeat with `offset=next_offset` until `done`; partial progress is committed per record. Uploaded JSON/BibTeX use `filename,content_base64` and preserve the same offset contract.
- `list` with `query=''`, `limit=40`, `offset=0`, `sort?`, `order?`, `archived=false` → `{items,total,limit,offset,search_mode,sort,order,archived,active_count,archived_count}`. Limit is clamped to 1–200, query to 500 characters. Sort accepts `title|author|year|journal|modified|created|citekey|jcr`; order accepts `asc|desc` and requires a sort field. Explicit sorts put missing values last and use stable paper IDs to break ties. Without a sort, queries of at least three characters use relevance; otherwise records use descending modification time. `author` uses the first author's family/literal name. `jcr` uses the latest supplied JCR year and its worst category quartile, while returning all supplied ranking records.
- `get` with `id,include_archived=false` → item (CSL fields plus `id,title,citekey,tags,pdf` boolean, actual `pdf_filename`, `parse`, `acquisition` when available, `page_count`, `archived`, `archived_at`, `created` and `modified`). `include_archived:true` permits metadata inspection only; it does not restore or open the PDF.
- `create` with `metadata` → a metadata-only item. It accepts no attachment paths; use `attach` separately. Duplicate DOI/citekey identities fail rather than overwrite another record.
- `update` with `id,metadata` → item. Catalog identity/runtime fields are protected. Attached PDFs retain the existing backup, portable metadata and atomic rename/write behavior.
- `archive` with `id` → archived item; `restore` with `id` → active item. Both preserve identity, managed PDF, annotations and relationships. Archived records are excluded from ordinary search/export and must be restored before reading or editing; no permanent-delete operation is exposed.
- `attach` with `id,path` → item; copy into managed storage
- `page` with `id,page=1,scale=1.25,include_layout=false,render_width?` → `{page,page_count,width,height,scale,requested_scale,limited,byte_limited,pixel_width,pixel_height,limits,rotation,image:<base64 PNG>,words:[[x0,y0,x1,y1,text,...]],annotations:[annotation],layout?}`。`include_layout:true` 在同一次 PDF 打开中附带既有 `page_layout` 形状的 `layout`，并把恢复用的页号限制在文档范围内；仍只对选定页进行渲染、提词和批注读取。默认请求继续拒绝越界页号。可选 `render_width` 是大于 0、最多 32,000 的有限像素宽度，以该宽度计算渲染比例并取代 `scale`；两条路径均受最高 8 倍、1,600 万像素、任一边最多 8,192 像素约束，分配前按向上取整后的像素核对。PNG 最多 16 MiB，过大的编码最多尝试 4 次降低比例；仍超限时明确报错，不写入 PDF。`requested_scale` 是请求比例，`scale` 是实际比例，`limited` 标明受限，`byte_limited` 标明为编码预算降低比例；`pixel_width/pixel_height` 返回实际像素，`limits` 返回 scale/pixels/side/png_bytes 限额。
- `page_layout` with `id` → `{page_count,pages:[{page,width,height,rotation}],...}`. At most 2,000 page geometries in the same displayed coordinate system as `page`; no text/image/annotation extraction or rasterization. The PDF closes before the short-lived worker exits.
- `annotations` with `id` → `{annotations:[{id,page,type,text,comment,author,rect,rects?,created,modified,...}]}`
- `annotation_catalog` with `id` → `{annotations,total,returned,total_exact,truncated,source_characters,source_characters_exact,ambiguous_ids,limits}`. Reads only the current PDF on demand. At most 1,000 user annotations are projected with `{id,version,page,type,source,identity_reliable,identity_source,text,comment,text_characters,comment_characters,source_characters,preview_truncated}`; text and comment previews are each capped at 240 Unicode characters. AI feedback is excluded. Duplicate PDF IDs are reported and cannot be selected reliably. A bounded scan may report an inexact total; returned rows must not then be called all annotations.
- `annotation_context_exact` with `id,annotation_refs:[{id,version}],selection?:{page,text},max_characters=24000` → `{item,annotation_refs,annotations,selection,source_characters,context_hash,coverage,limits}`. Requires at most 1,000 distinct current SHA-256 versions and reads complete source text. Selection is capped at 8,000 characters. Missing, edited, duplicate-ID, over-budget or incomplete-scan sources fail explicitly; the operation never silently truncates the selected content. `coverage` contains `{requested,included,total,total_exact,all}`. The worker accepts a source-character budget of 1–96,000; deployed native-chat configuration restricts its setting to 1,000–96,000.
- `annotate` with `id,page,type='highlight'|'underline'|'strikeout'|'note'|'ink',rects?,paths?,width=2,annotation_id?,text,comment,author='Reader',color='#ffdb66'` → `{annotation,...}`. Text markup requires `rects:[[x0,y0,x1,y1],...]`; note may omit them. Ink requires `paths:[[[x,y],...],...]` in the same displayed PDF-point coordinates as `page` (rotation already applied). Each of 1–64 strokes has at least two points; at most 4,096 total points and 128 KiB compact serialized paths. Coordinates must be finite numbers within the displayed page, and ink `width` must be 0.5–8 PDF points. Ink is a standard `/Subtype /Ink` annotation with native `/InkList`; readback returns `paths,width` from the PDF itself, including external Ink. The optional ink-only lowercase UUID `annotation_id` makes exact retries idempotent under the PDF write lock: an identical existing object returns `duplicate:true` without rewriting; different content rejects and requires a new ID. Comment updates retain the saved type/color/position and ink geometry. JSON exports include ink paths/width; XFDF uses standard `<ink><inklist><gesture>` plus width/color in PDF user space, including rotated and cropped pages. No general annotations JSON/XFDF importer is exposed; portable round trips use PDF export/import.
- External Ink exceeding the geometry limits remains intact in PDF exports and raster rendering; its bounded projection returns `paths:[],geometry_truncated:true`, and XFDF omits it with a warning. JSON preserves that explicit truncation marker. Such annotations cannot be used as exact references until split in a PDF editor. Ink geometry contributes to the existing 2,000,000-character page/list response budget and has a separate 2,000,000-character exact-reference geometry budget. Reference versions include ink paths, width and color so a changed stroke cannot retain a stale reference version.
- `annotation_update` with `id,annotation_id,comment` → `{annotation}`
- `annotation_delete` with `id,annotation_id` → `{deleted:true}`
- `export_annotations` with `id,format='xfdf'|'json'|'markdown'` → `{text,filename,mime}`
- `export_pdf` with `id` → `{path,filename}` (Node streams managed path, not browser-supplied path)
- `link` with `source,target,relation='related'|'supports'|'contradicts'|'cites',note=''` → link
- `graph` with `id?,limit=80,offset=0,focus_id?,view='all'|'citations'` → `{nodes,edges,truncated,warnings,scope:{paper_id,max_nodes,max_edges,paper_offset?,paper_count?,total_papers?,next_offset?,previous_offset?},semantics,node_types,relations}`。`limit` 限制为 1–200 个节点，最多 400 条关系；界面显式请求 100 个节点。省略 `id` 时按当前目录排序读取每批最多 `min(limit,40)` 篇有效文献，`offset` 接受 0–10,000,000 的整数；`scope` 额外返回当前偏移、该批篇数、有效文献总数以及上一批／下一批偏移，无对应批次时为 `null`。这些数量描述文献窗口，不能当作已完整显示的节点／关系数量；`truncated` 与 `warnings` 保留部分投影的提示。传入 `id` 则读取该论文图谱，不返回目录分页字段。节点和关系区分 `provenance:'catalog-metadata'|'user-asserted'` 与 `editable`，原有论文联系另标 `legacy:true`；该操作只投影已存资料与读者关系，不推断全库学术结论。
  新增 `view:'all'|'citations'`（默认 all）、`focus_id?`：全库窗口优先保留指定论文及其关系；不改变目录分页游标。citations 在生成阶段排除作者／标签／科学概念，保留 `cites` 及已保存参考文献 DOI 的唯一库内匹配，不联网推断引用。all 还投影每篇最近最多 20 份未否决的非空知识草稿，节点和关系保留 `provenance:'ai-analysis',review_status,draft_id,evidence`；仅显示，不自动接受草稿，截断通过 `truncated` 提示。

- `graph_statistics {}` → `{scope:'active-library',total_papers,years:{known,missing,items:[{year,count}],other_count,truncated,maximum_rows:200},citations:{known_papers,missing_papers,sources:[{id,label,fields,known,missing,buckets:[{label,count}]}]},semantics}`。只读、单次 SQL 汇总整个有效文献目录，排除回收站，与 `graph` 当前 40 篇窗口无关；不读取 PDF、不调用模型或联网更新。

  年份取已保存 `issued.date-parts[0][0]` 中 1–9999 的整数，无法识别的记入 `missing`。`items` 按年份升序返回最近最多 200 个不同年份，其余较早年份的文献数汇总到 `other_count`，不丢弃全库计数；存在该汇总时 `truncated:true`。`known + missing = total_papers`，`items[*].count` 之和加 `other_count` 等于 `known`。

  引用量只识别保存的来源字段：Crossref 顶层 `is-referenced-by-count` 或 `crossref.is-referenced-by-count`（两者均有效时优先顶层）、OpenAlex 的 `openalex.cited_by_count`、Semantic Scholar 的 `semantic_scholar.citationCount`；`sources` 固定返回这 3 个来源，`fields` 列出所用路径。只接受 0–1,000,000,000 的整数，缺失、布尔值、数字字符串、负数、超限值及泛化的 `citation_count`／参考文献数量均不当作引用量。每个来源返回 `0`、`1–9`、`10–49`、`50–99`、`100–499`、`500+` 共 6 个区间及已知／未知覆盖数，最多 18 个区间；来源快照口径分别显示，不相加。`known_papers` 按至少一个来源已知的文献去重计数，不能累加来源的 `known` 得到；`missing_papers` 是全库尚无可识别引用量的文献数。无可识别元数据时显示尚未采集，不能把未知文献放进「0 次引用」区间；接口不核验这些已保存快照的时效。
- `graph_node_put` with `id,node_id?,type,label,description?,evidence?` → editable node. Omit `node_id` to create; supply it to edit a node owned by that paper. Type accepts `method|dataset|claim|evidence|concept|author|institution`.
- `graph_node_delete` with `id,node_id` → `{deleted:true,node_id,removed_edges}`; deletes that editable node and its attached reader-authored relationships.
- `graph_edge_put` with `id,edge_id?,source,target,relation,evidence?` → editable directed edge. Omit `edge_id` to create. Endpoints must belong to the current paper graph; self-links and duplicate directed relationships fail. Relation accepts `supports|contradicts|uses|evaluates|derived_from|explains|extends|cites|related|authored_by|affiliated_with|published_by`.
- `graph_edge_delete` with `id,edge_id` → `{deleted:true,edge_id}`.
- `feedback_context` with `id,annotation_ids?` → `{item,annotations,prompt,mode,context_hash}`; bounded source context, source treated as untrusted data. `mode` is `single` for one annotation and `per-annotation` for several, where the prompt requires exactly one JSON entry per provided annotation id (`{"replies":[{"annotation_id":…,"comment":…}]}`).
- `save_feedback` with `id,text?,model,annotation_ids,expected_context_hash?,replies?` → AI-labelled standard PDF note(s) for attached papers; digest checked inside write lock when supplied. Exactly one of `text` (one answer) or `replies` (one entry per annotation, 1–100 entries, 1–8000 characters each, unique ids inside the generated context) is required. With `replies` the whole set is written in **one** atomic PDF replacement and every note carries `annotation_ids:[its own source]` plus `/IRT` to it, so an answer is never duplicated across annotations; unanswered ids are reported in `missing` instead of being filled with another annotation's text. Internal adapter operation, not browser-callable.
- `save_conversation_feedback` with `id,text,model,annotation_ids,source_session_id,source_message_id,page=1,source_snapshot_ids?` → portable AI reply. Requires an attached PDF and 1–28,000 text characters. Host-verified associations accept at most 1,000 unique IDs / 64,000 serialized characters and four snapshot hashes. Missing, ambiguous or AI source annotations reject before writing. Associated replies are placed near the first source on its page with native PDF `/IRT`; all source IDs remain in PDF metadata, while the reply is displayed only once under its native parent (or the first available source). Session/message IDs are bounded to 200 characters. Duplicate pairs preserve the existing body; an old unassociated copy may gain verified links atomically. The return includes `annotation_id,page,kind:'ai-feedback',model,annotation_ids,reply_to?,source_kind:'dsh-conversation',source_session_id,source_message_id,source_snapshot_ids,generated,comment,duplicate`. `comment` holds the body; `text` retains its selected-PDF-text meaning. This is an internal worker operation, never browser JSON.
- `feedback` with `id` → `{feedback:[...]}`

Node additions:

- `metadata_lookup` with `id` → `{item,author_candidates,warnings,provenance}`。查询选中文献已保存的 DOI、URL 或 arXiv 标识；缺失时按需本地检查 PDF 前 3 页标识符，再以题名查询 Crossref／arXiv（每源最多 5 个候选）。不发送 PDF 正文。DOI 必须一致，其他路径要求唯一的精确规范化题名匹配；歧义结果不自动选择。仅填缺失字段，保留人工资料及 JCR；缺名作者仅在姓氏唯一匹配时补全。完整远端作者表另供用户明确采用。返回编辑草稿，调用本身不写目录或 PDF；网络期间资料变化会核对，草稿上限 256 KiB。固定题录服务遇本地代理 198.18/15 Fake-IP 时，使用 Cloudflare 加密 DNS 解析真实公网地址，继续执行公网校验与连接地址固定；一般 URL、重定向和显式测试解析器无此例外。
- `cite` with `ids:[...],format='apa'|'biblatex'|'csl-json'` → `{text,html?,filename,mime}`
- `export_library` with `format='biblatex'|'csl-json'` → `{text,filename,mime,count}`; consistent metadata snapshot, citation formatter batches100 in short-lived processes, max10000 records
- `import` with exactly one of `doi`, `url`, `path`, `items`, or `content_base64`. `url` accepts public HTTP(S), DOI and arXiv identifiers. A downloaded PDF is parsed before catalog insertion. Local PDFs use bounded inspection, optionally enrich from Crossref only after exact normalized parsed-title matching, and preserve portable user metadata. Results extend the core envelope with `acquisition:{status:'downloaded'|'metadata_only'|'reused',...}` and warnings. Always use `item.pdf` to determine whether a managed PDF exists. Metadata-only imports do not imply a saved full text.
- The reader rail builds reply threads in `web/annotation-threads.js` (`window.PaperAnnotationThreads.threads`), which nests a per-annotation reply only under its own note and shows any combined note once; `web/app.js` keeps an identical inline fallback so an already-running host that has not yet served the new asset still renders without duplication.
- `ai_feedback` with `id,annotation_ids?,provider,model,reasoning_effort?` is the compatibility path for independent annotation feedback. It invokes the configured LLM service and persists a complete result after checking the annotation snapshot; it does not create or continue a native conversation. Optional `session_id` is attribution, not a server route resolver. With one selected annotation the answer is one note. With several, the reply JSON is validated by `splitFeedbackReplies`: every `annotation_id` must be one of the provided ones, ids may not repeat, comments must be non-empty and at most 8,000 characters, and an answer may not cover more annotations than were selected. A violation fails the request before any write. A model that returns one combined answer instead of JSON is stored once (never copied) and reported with `combined:true` plus a warning; unanswered ids are reported as warnings. The installed Harness reader uses the `chat_*` operations below for its conversation workflow.

## Research metadata and graph records

`author`, `editor` and `translator` accept up to 300 people. Each person's `affiliation` is an array of at most 30 `{name,id?,ror?,source?}` records; institution names are limited to 500 characters, optional identity/source text to 2,000. `publication_dates` accepts only `{published?,online?,print?,received?,accepted?}` with calendar-valid `YYYY`, `YYYY-MM` or `YYYY-MM-DD` values. Missing dates stay absent; no month or day is synthesized.

`journal_rankings` holds at most 30 `{system:'JCR',year,category,quartile,source,verified_at?}` records. Year is an integer from 1900 to 9999, category is required and at most 500 characters, quartile is `Q1|Q2|Q3|Q4`, and the required source is at most 2,000 characters. Optional `verified_at` is an ISO date or datetime. Catalog metadata is capped at 256 KiB. Rankings must come from a sourced import or manual entry; lookup does not infer them from citation counts, an impact factor or publisher prose.

Crossref supplies author affiliations and explicit publication/online/print/accepted fields. HTML lookup uses explicit citation author-institution and date tags; it never treats registry creation/deposit time or ordinary page text as a manuscript date. arXiv's original submission date remains its preprint `issued` date, not a journal `publication_dates` value. The reusable Node `resolveMetadata(target, options)` returns `{status:'metadata_only'|'unavailable',metadata?,provenance,warnings}` for a DOI, arXiv identifier or public landing URL. It creates no files, requests at most one landing page in addition to the identifier API, skips known PDF candidates, closes declared PDF responses before reading their bodies, and stops signature-detected PDFs. Existing public-network limits apply. This is source retrieval; `metadata_lookup` adds the current-record identity and merge checks.

When the deployment sets `translationServer` to a loopback HTTP address (for example a self-hosted Zotero translation-server), `metadata_lookup` that produced no metadata through the primary path retries the same target through the sidecar: identifiers go to `/search`, public landing URLs to `/web`. The plugin never bundles, installs or starts that service, and only identifiers/URLs are sent — never PDF text, notes or drafts. Candidate items are mapped conservatively (unknown values stay absent, unparsable dates are dropped) and must pass the unchanged identity gates: exact DOI equality, or an exact normalized title of at least eight characters. A sidecar-supplied draft records `provenance.provider:'translation-server'`; mismatched or absent candidates surface as warnings. `src/translation-server.mjs` enforces the loopback-only address, a 1 MiB response budget, POST-only requests and a 15-second deadline.

Editable graph nodes return `{id,paper_id,type,label,description,evidence,provenance:'user-asserted',editable:true,created,modified}`. Editable edges return the same ownership/provenance fields with `source,target,relation` instead of node fields. Node labels are required and at most 500 characters; descriptions are at most 4,000. Evidence is `{page?,quote?,note?,source?,annotation_id?}`: page is `null` or a known positive integer up to 100,000, quote allows 4,000 characters, note 2,000, source 1,000 and annotation ID 200. Unknown page locations remain `null`; graph evidence does not itself verify that a passage occurs there.

Each paper stores at most 2,000 reader nodes and 2,000 reader relationships. Metadata-derived nodes are read-only, paper-scoped and distinct from reader assertions; matching names alone do not establish a shared person identity. Metadata changes can leave an existing reader relationship's endpoint unavailable: the record remains stored and the projection reports a warning instead of rebinding it to a different author. `truncated:true` also covers omitted nodes/edges and ambiguous identities. See the [workbench contract](ui-review-design.md) for the reading and maintenance workflow.

## Unified dataset catalog and knowledge

All calls use the existing JSON action carrier. `resource_list` accepts `kind:all|paper|dataset` plus bounded pagination, search, sorting and archived scope. Paper IDs and old APIs remain unchanged. Creates use `expected_revision:0`; dataset, release, asset, link and note updates use the returned integer revision. Stale updates return HTTP 409 with `code:STATE_CONFLICT` and `current`.

| Actions | Key input / behavior |
|---|---|
| `dataset_put`, `dataset_get`, `dataset_archive`, `dataset_restore` | `id?`, `metadata`, revision; get includes at most 20 children per kind with totals |
| `dataset_release_put`, `dataset_release_get`, `dataset_release_list` | Parent `id`, optional `release_id`; release metadata carries its own version/DOI/citekey |
| `dataset_asset_put`, `dataset_asset_list`, `dataset_asset_preview` | Parent `id`, optional `asset_id`, `path` or `url`, optional `release_id`; linked files only |
| `dataset_link_put`, `dataset_link_list`, `dataset_link_delete` | `paper_id,dataset_id,release_id?,relation,role?,scope?,evidence,review_status,origin`; list by paper or dataset |
| `dataset_graph_promote` | `paper_id,node_id,dataset_id?,metadata?,expected_revision:0`; retains old node and explicit mapping; no inferred usage |
| `dataset_cite` | `id,release_id?,format:apa|biblatex|csl-json`; existing CSL formatter and missing-field warnings |
| `dataset_import` | Up to 100 input items per call; CSL dataset or explicitly identified release with parent binding; conflicts do not replace existing metadata |
| `resource_export` | `kind,offset,limit<=100,expected_catalog_revision?`; at most 4 MiB per page; use returned `next_offset` and catalog revision |
| `export_library` | BibLaTeX or CSL JSON citation metadata for papers, datasets and releases; 24 MiB metadata budget; no files, links or notes backup |

Link relations are `mentions|cites|uses|produces|describes`. Evidence is an array; supported fields include `quote,page,printed_page,section,source_uri,source_id,source_kind,source_hash,annotation_id,annotation_version`. Unknown page is null. Explicit review is distinct from scientific verification. AI tool calls force `origin:ai,review_status:needs-review`; a manual accepted link requires some source evidence.

Preview is UTF-8 CSV/TSV/JSONL only, with a 100-row, 50-column, 512-KiB response cap, independent 4-MiB input, 64-KiB physical-line, 8192-character field and 2-second parse budgets. `sample_only:true,total_rows:null`; `status` is `ready|partial|error|missing|unsupported`. A partial result retains valid rows and warnings; no cell is silently truncated. `sample_sha256` covers consumed bytes, not the whole file; `file_sha256` stays null. File replacement cannot silently rebind a path. Other formats remain registered without parsing.

Knowledge calls scope records by `entity:{kind:paper|dataset|release,id}`:

| Actions | Key input / behavior |
|---|---|
| `knowledge_source_put/get/list/check` | Put a fixed `annotation|official-excerpt|user-text|metadata|source-note`; annotations require exact `annotation_ref:{id,version}` and are read from PDF. Official excerpts require URL. Check re-reads one saved annotation explicitly; other sources remain snapshot-only. |
| `knowledge_generate` | Native Harness only: `entity,source_ids,mode:graph|note,request_id,instruction?`. Host resolves model; browser provider/model overrides are ignored. |
| `knowledge_draft_put/get/list` | `entity,source_ids,mode,title,body?,nodes?,edges?,assertions?`; every proposal starts `needs-review`; author/LLM origin is separate. |
| `knowledge_draft_review` | `id,expected_revision,decision:accepted|rejected,reviewed_by:user`; UI only, no model tool. Does not automatically create Markdown. |
| `knowledge_draft_lint` | `id`. Read-only structural findings over one saved draft: unsupported claims/gaps, isolated nodes, evidence unused by assertions/observations, duplicate relations, dangling endpoints and observations without a source node. Reports severity counts and up to 200 findings; never repairs or rewrites. |
| `knowledge_note_put/get/list` | `id?,entity,title,body,source_ids,expected_revision`; revisioned Markdown under `knowledge/notes`, with durable write intent recovery. |
| `knowledge_export` | 1–20 explicitly selected entities, `format:library-json|rkos-v3`; at most 100 accepted drafts/notes, 200 sources/nodes, 400 relations and 4 MiB. Over-budget scope fails explicitly. |

Generation is at most 40 sources / 24,000 characters and two concurrent requests, with native model output defaulting to 8192 tokens (the configured language-output limit) and a 120-second deadline. Pending, failed, committing and complete records are host-durable; uncertain retries retain request identity. Explicit new-generation retry is required after failure/interruption. A completed request replays its draft without another model call. No model tools, full-library scans, file discovery or background graph extraction run in this path.

`knowledge_source_put` 也支持从既有提取快照创建短摘录：`entity:{kind:"paper",id},kind:"source-note",parent_source_id,text`。后端要求父来源属于同一论文、含服务器提取的 `selected-pdf-page` 文件版本，且 `text` 精确包含于父文本；继承真实页码、Markdown 表示与文件版本，记录父来源 ID、哈希及摘录位置。客户端提供的页码或 PDF 证明不会被采用。返回的 `pdf_snapshot.kind` 为 `selected-source-excerpt`，`excerpt_only:true`，不宣称全文覆盖；父快照保持不变，不重新读取或下载 PDF。此能力用于笔记的短引用绑定，仍受 40 来源／24000 字符的保存上限约束。

Structured nodes use stable typed IDs; Evidence binds an exact selected source excerpt, Observation points to a source node, and Assertion relates evidence/observation to Claim/Gap. Edge uses separately validated typed endpoints. `library-json` contains selected accepted graphs/notes plus referenced snapshots and identity metadata; it is not a whole-library restore format. `rkos-v3` adds role-separated bibliography/sidecars, mappings and losses; native dataset sources are not disguised as Paper records. Runtime exports use the bounded adapter's structural checks; the upstream parser is exercised separately by the synthetic validation script, never auto-discovered at runtime.

## Research challenge mining

`challenge_scan` mines deterministic, model-free difficulty candidates from explicitly selected papers. It is available over the browser/CLI API (the native tool and corpus panel arrive with the later stages). No model is called: `model_calls` is always `0`.

| Field | Contract |
| --- | --- |
| `ids` | 1–50 unique, well-formed paper ids. The scan never searches the catalog on its own. |
| `sections` | Optional subset of known section names (`limitations`, `future-work`, `threats-to-validity`, `discussion`, `conclusion`, `introduction`, `background`, `related-work`, `results`, `experiment`, `method`); default picks up to six by that priority order from the sections actually found. |
| Result | `{schema:'paper-library-challenge-candidates.v1', generated_at, scope:{requested,scanned,skipped}, budgets, rules, totals, papers, model_calls}`. |

Sections are recognised from whole heading lines (numbered or not, English or Chinese) and end at back matter (`references`, `bibliography`, `acknowledgements`, `appendix`, …). Unrecognised numbered subsection headings are treated as structure and never scanned, so subsection prose stays inside its parent section. Sentences are split with an abbreviation guard (`et al.`, `e.g.`, initials) so a citation does not truncate evidence.

Budgets: 50 papers per run, 200 pages and 24,000 characters per paper, 6 sections and 40 candidates per paper, 1,200 characters per candidate, and 400 candidates / 200,000 characters per run; `truncated` marks a paper or the whole run that hit a limit. Every candidate keeps its section, real page and matched rule ids (`en-limitation`, `en-challenge`, `en-contrast`, `en-negative`, `en-open`, `zh-limitation`, `zh-challenge`, `zh-contrast`, `zh-negative`, `zh-open`). Papers without a PDF, archived papers and unknown ids are reported in `scope.skipped` with a reason instead of failing the run. No PDF text is sent anywhere and no section is inferred for a page whose text is missing.

### Bounded extraction (P2)

`challenge_extract_start|get|cancel` 执行模型分析。`challenge_extract_start` 接收 `{id, request_id, sections?}`，只处理一篇已关联 PDF 的在库文献；宿主将候选材料固定为不可变来源（`challenge_sources`），使用该论文配置的模型进行无工具调用，返回有界 JSON 草稿。结果保存为 `needs-review` 的 `knowledge_draft`；`mode:graph`、`origin:llm` 和确定性的 `challenge-<hash>` 请求标识保证重复请求不会重复写入。

| Field | Contract |
| --- | --- |
| Output shape | `nodes` (`gap`/`question`/`evidence` only), `edges`, `assertions`. Gap and question nodes require `source_status` (`author-stated` or `inferred`; anything else is rejected). Evidence nodes require a `source_id` from the frozen sources and a quote that occurs verbatim, at most 400 characters. |
| Linkage | Every gap must be the object of at least one assertion whose subject is an evidence node; every question must be the object of a `limits`/`blocks` edge from a gap. This matches the controlled vocabulary, where only claim/gap may be assertion objects. |
| Limits | 20 nodes, 30 relations, one paper per job, one job at a time, 40 sources / 24,000 characters per paper (the frozen candidate budget). |
| States | queued/reading/generating/committing/complete/partial/failed/cancelled; a running record without an owned flight reads as `interrupted`. Duplicate starts share one flight; a completed request returns its saved draft without another model call; a new `request_id` is required to regenerate. |
| Failure | Unsupported status, inexact quotes, unbacked gaps, unlinked questions and unknown source ids fail the job with a visible reason and no draft. Cancellation aborts the owned model call. |

The standalone preview can read saved records but cannot generate (no agent), exactly like the full-paper analysis path. `status.challenge_mining` reports whether the host route exists; `status.challenge_scan` is always true.

### Cross-paper theme aggregation (P3)

`challenge_themes` aggregates **saved** difficulty records — `gap`/`question` nodes carrying `source_status` in accepted knowledge drafts — into corpus themes. It opens no PDF and calls no model (`model_calls` is always `0`); the corpus is the explicit id list, and `include:'all'` also reads `needs-review` drafts (each exported paper records its `draft_status`).

| Field | Contract |
| --- | --- |
| `ids` | 1–200 unique, well-formed paper ids. Aggregation reads saved drafts only, so this bound is wider than the 50-paper PDF scan bound in §Research challenge mining; no whole-catalog scan happens. |
| `include` | `accepted` (default) or `all`. |
| `persist` | Default `true`. Themes are stored per corpus scope as `needs-review` records with a revision; re-running bumps the revision and keeps a `previous` summary. |
| Result | `{schema:'paper-library-challenge-themes.v1', generated_at, scope:{hash,requested,scanned,skipped,include}, totals, merge_suggestions, themes, model_calls}`. |

Labels are keyed by NFKC-normalised, punctuation-stripped lowercase text, so “Cross-city generalization is unclear” and “cross city generalization is unclear!” land in one theme. Each theme reports `paper_count`, `record_count`, `evidence_count`, a `years` histogram (`min`/`max`), per-`source_status` counts, up to 40 exact quotes with their real pages, the normalised `variants`, and up to 50 member papers. Quotes come from frozen sources; a missing quote stays missing. `merge_suggestions` proposes label pairs whose token overlap (Jaccard) is at least 0.6 — a suggestion is never applied automatically.

`challenge_theme_list` (`scope?`, `status?`, `limit`, `offset`) and `challenge_theme_get` (`id`) read stored themes with bounded papers/quotes. `challenge_theme_review` (`id`, `decision:accepted|rejected`, `reviewed_by:'user'`, `expected_revision`) is the only way a theme changes status; a non-user reviewer or a stale revision is rejected.

`challenge_theme_merge` (`theme_ids` 2–10 from one scope, `expected_revisions` — a map keyed by theme id or, for tool surfaces, positions aligned with `theme_ids` — `reviewed_by:'user'`, optional `label`) folds reviewed themes into one new `needs-review` theme and marks every member `status:'merged'` with `superseded_by`. It only unions stored records: papers, years, source-status counts and quotes are summed, never inferred.

`challenge_theme_suggest_start|get|cancel` are the optional model stage. They need `{id, scope, request_id, theme_ids}` (2–40 `needs-review` themes); the paper id is used only to borrow that paper's DSH model route, and the prompt carries theme ids, labels, variants, paper counts and statuses — never PDF text. The validated reply may only group the provided ids (each id at most once, 2–8 members per group, bounded label/reason); unknown ids, duplicate members, bad keys and oversized payloads fail the job with no proposal saved. Every group is written as `needs-review`, and applying one still goes through `challenge_theme_merge`.

`challenge_export` (`ids`, `scope?`, `include_unreviewed?`, optional `merge_suggestions`) writes three files under the library's `exports/` directory with atomic replacement: `challenges.csv` (one row per theme/paper/quote: theme id, label, status, revision, paper id, citekey, year, node id, source_status, page, quote), `challenges.md` (coverage, year spread, source-status counts, variants, per-quote `[@citekey p.N]` lines, pending merge suggestions and the provenance note) and `challenges.bib` (only catalog metadata; missing fields are omitted, never invented). Only `accepted` themes are exported unless `include_unreviewed:true`; exporting an empty scope fails with `CHALLENGE_MISSING`. The 8 MiB per-file export budget is enforced before any write.

### Comparison, structural check and review packet (P4)

`challenge_theme_check` (`scope`, optional `statuses`) is a read-only structural pass over stored themes. Findings use stable codes: `theme-without-evidence` (error), `theme-single-paper` and `theme-inferred-only` (warning), `theme-unreviewed`, `theme-merged-member` and `theme-revised` (info). It writes nothing, calls no model and reports `counts` plus `by_status`.

`challenge_comparison` (`ids`, `scope?`, `checklist_text` **or** `checklist_path`, optional `checklist_label`/`checklist_date`, optional `statuses`) compares stored themes against a checklist the user owns. Entries come from bullet lines, or plain lines when there are no bullets, or a multi-heading outline; a lone document title is never an entry. Matching is deterministic token overlap — whitespace tokens for Latin text and character bigrams for CJK — with `covered` at ≥ 0.5, `partial` at ≥ 0.2 and `gap` below that (thresholds are returned in the result). A file path must end in `.md/.markdown/.txt/.text/.json/.csv/.bib`, may not exceed 1 MiB, and its recorded `checklist.date` is the file's modification date in UTC unless `checklist_date` (`YYYY-MM-DD`) is given; pasted text is recorded as `pasted text`. The result keeps every entry with up to ten candidate matches and overlaps, the per-theme entry lists, the uncovered `gaps`, the `unmatched_themes`, and a `manual_review_note` stating that only wording was compared. Reports are stored per corpus scope and checklist hash with a revision (`challenge_comparison_list`, `challenge_comparison_get`). By default every stored status is compared, because a comparison is a report, not an export; each theme's status is shown.

`challenge_review_packet` (`ids`, `scope?`, optional `comparison_id`, optional `statuses`) writes the human review packet: `exports/challenges-review-packet.md` (findings first, then every theme with coverage, years, `source_status` counters and `[@citekey p.N]` quotes, then the comparison table, then the manual note) and `exports/challenges-review-packet.json` (the same content plus `provenance.review_actions`, which names the exact `challenge_theme_review` / `challenge_theme_merge` / `challenge_export` payloads a reviewer should send). A comparison from another corpus scope is refused. Both files respect the 8 MiB export budget and both are written atomically; `model_calls` stays `0`.

`latex_review_list` 对原锚点失效的记录附加只读 `relocation`，不改变 `anchor`、`stale`、`version` 或保存内容。`status` 为 `matched/ambiguous/unmatched/unsupported/budget`；成功包含 `method:exact|normalized|fuzzy`、0–1的 `score`、当前 `anchor`，跨页PDF另含每页 `anchors`（首个也是跳转位置）。偏移为原始Unicode码点，PDF矩形沿用显示坐标含页面旋转。UI只用这些字段恢复定位与虚线预览，不自动迁移原生PDF批注；JSON包含匹配结果，Markdown保留原始和当前匹配位置，PDF导出保留原版本对象及JSON附件。

匹配仅限同一源码文件或当前完整PDF范围。唯一原文／NFC加空白规范化匹配至少16个字母或数字（含中文）；模糊路径至少48个、最多2,048字符，相似度和原引用覆盖率均不低于96%，另一处达到90%或分数过于接近即拒绝。输入文本≤1,000,000字符、引用≤20,000字符、候选≤256、单条比较预算12,000,000；PDF≤80页／120,000词／1,000,000字符，列表共享文本工作预算8,000,000字符。超限返回budget而非将局部扫描视作唯一；短引用、空引用、无法读取或其他入口迁移的PDF记录保持待重定位。此步骤无模型调用、不修改源码、原PDF或批注文件。

`latex_ai_ask {id,path?,question,review_note?:{id,version}}` 与 `latex_ai_propose {id,path?,instruction,review_note?:{id,version}}` 可明确引用一条已保存的源码／PDF 批注，模型路由仍由当前设置传入。服务端按当前项目入口读取至多300条既有自审记录，核对批注ID与版本；不使用调用方附带的评论或摘录。模型前后均重新核对项目绑定和批注版本，删除、编辑或切换入口后拒绝迟到结果。批注引用不能与编辑器 `selection` 混用；源码批注只针对其 `anchor.path`，省略 `path` 时使用该文件，明确传入不同文件会拒绝；PDF批注必须明确指定当前讨论或修改的源码 `path`，不推测页码到源码的位置。旧锚点以历史材料说明，不能冒充当前来源位置。

模型材料继续限制源码24,000字符，额外批注摘录与评论各最多8,000字符，截断有明确标记；仅把服务端保存内容作为不可信引用数据。结果的 `entry`、提案及最近4条协作日志携带 `review_note:{id,version,kind,stale}`，不另存批注正文副本；无改动的批注提案也保留一条0处改动记录。接受／放弃提案的日志保留同一批注身份，响应也返回该条 `entry`；`latex_ai_discard` 可带 `proposal_id` 核对待放弃的精确提案，旧按钮不会丢弃另一窗口生成的新提案。提案仍以唯一原文及源码修订CAS核验，只在明确接受后写源码，不自动解决原批注或改写PDF。

提问与提案可传 `retrieval:{project:boolean,public_queries:string[]}`。旧请求省略该字段或关闭两类检索时沿用单次模型调用。工作台默认启用 `project`；公开检索仅接受本次明确填写的至多 3 条单行关键词（每条 ≤200 字符）。模型只可按编号选择这些词，项目内容、批注和问句不会自动发往公开检索服务。

写作工具只在本次对话中提供。`list_project_files`、`search_project`、`read_project_file` 和 `read_project_pdf` 分别对应内部 `latex_retrieval_list`、`latex_search`、`latex_retrieval_read`、`latex_pdf_text`；服务端固定项目 ID、根目录和绑定代次。读取已保存的相对路径，逐级拒绝符号链接、隐藏与常见凭据文件；不支持安全打开文件的平台不启用项目检索。列表每批最多 50 项；扫描最多 2,000 项／2 秒，字面搜索最多 4 MiB／20 条命中，单文本 ≤1 MiB，读取 ≤200 行；单 PDF ≤64 MiB、每次至多 3 页，仅提取已有文字。`scholar_search` 每词最多 5 条 Crossref／arXiv 结果，只返回题录或摘要，不下载全文，不跟随检索重定向。

本次模型检索最多 4 轮、8 次工具请求、120 秒，工具结果累计最多 32,000 字符。`entry.retrieval` 与提案携带 `sources`（实际返回的 `[F#]` 文件／PDF 位置、修订或 `[S#]` 公开文献身份）、`trace`、`public_search` 状态和截断标记；不另存工具参数、正文、摘要或检索词。未成功调用工具时报告失败；未返回的证据编号不允许入库。回答与提案不因检索扩大写入目标；停止、项目绑定或批注版本改变可阻止迟到结果。检索动作不加入全局 DSH 工具目录，也不接受浏览器直接提交。

`latex_ai_translate {id,selection,target_language?:'auto'|'zh-CN'|'en',model_override?,prompt?}` 翻译当前明确选择的编辑草稿，选文最多 8,000 字符，可含未保存改动；不读取整个源文件，也不写回源稿。项目覆盖优先于 `language.settings`，再跟随 DSH 默认模型；显式覆盖须匹配宿主已配置模型目录。补充提示词最多 2,000 字符，结果最多 8,000 字符；省略目标语言时跟随语言设置（缺省自动识别），中文正文译为英文，其他正文译为中文，显式方向覆盖该判断。返回 `{id,answer,model,source:'editor-selection',target_language,prompt_version}`，界面先供查看和复制。项目模型、语言和提示词通过既有主机状态保存，界面只把名称包含 flash／mini 等的模型标为轻量候选；宿主未提供价格与延迟时不作最低价或最快保证。

英语拼写检查完全在浏览器本地执行，开启时才加载 `latex-spelling.js` 中的 Hunspell 字典；不发送源文或调用模型。它只检查当前文件的有界自然语言片段，跳过常见 LaTeX 命令、数学与引用键，属于拼写提示而非语法或编译检查。

`latex_engine` 是全部 LaTeX 项目共享的编译偏好，取值为 `xelatex`（默认）、`pdflatex` 或 `lualatex`。
通过现有 `settings_update` 的 `patch` 写入，并继续使用 `expected_revision`；`latex_ws_status.settings.engine` 返回当前生效值。
直接调用 `latex_compile` 的 `engine` 参数保持原接口；工作台会将已保存的偏好传入该参数。
`latex_theme` 为工作台局部配色，取值 `system`（默认）、`parchment`、`midnight`，同样使用设置修订号保存。

HTTP `GET latex-version-pdf/<version_id>?review=<可选编译哈希>` 下载当前版本或清单中的批注副本，继续使用宿主认证和受限路径。上述 `version_*` 也可经 `library_latex` 的同名操作读取；项目关联通过编辑工具完成。原始项目仍留在原目录，只有手动版本快照复制到私有 `latex-versions/`，不会写入原 PDF。

Tool metadata is a closed subset: `title,type,citekey,DOI,URL,abstract,author,editor,container-title,publisher,volume,issue,page,issued,tags,publication_dates,journal_rankings`. Its person schema accepts `family,given,literal,ORCID,affiliation`, with affiliation `{name,ror?,source?}`. Tool `issued` uses CSL `date-parts`. Graph evidence uses the closed schema above. Paths and runtime state cannot enter structured metadata. Each tool request is capped at 128 KiB before dispatch; core field limits still apply. `library_annotate` requires `rects` for text markup or `paths` for Ink; note placement may omit `rects`.

Mutation tools pass through the configured native approval pipeline; `requireToolApproval` defaults to true and preserves any existing denial. Read tools do not start a model. `library_feedback` uses the calling Agent's configured model route by default and remains the compatibility feedback operation, not `chat_send`. `metadata_lookup` is a Node/browser operation, not an additional registered native tool.

## External sources (synced corpora)

`external_sources`, `external_files` and the staged tree under `<library>/external/` let the library index PDF corpora that a separate sync/backup service maintains. Roots always come from deployment configuration (`externalSources`, `syncConfig`) or from the live settings `sync_config` / `external_sources`; a tool argument can never select a path. A sync config only offers candidates: an entry is indexed when it is selected by id, by `{"select":"all"}`, or by giving an absolute root, and directories inside `$DSH_HOME` are never offered. One root keeps one source id — a second id for an already indexed directory is refused with `conflict` instead of duplicating its records. `external_scan` walks a root, reads only directory entries and size/mtime, records filename-derived metadata as `parse.field_sources = synced-filename` with `needs_review`, and creates one symlink per PDF; unchanged files are skipped from the durable records, and at most 200 new files (limit 2,000) are indexed per call with `pending` reporting the remainder. `external_prune` removes only links whose file is gone. `external_files` keeps `missing = 1` rows and never deletes a paper, so annotations and graphs survive a disappearing file.

`pdf_path` returns the staged link for an external record; every write goes through `_writable_pdf`, which promotes the file into `pdfs/` first (`external_source.promoted`), so a synced directory is never modified. Sources may not live inside the library, staged paths may not escape their source directory, and an existing regular file at a staged path is refused rather than overwritten. Design and configuration: [external-sources.md](external-sources.md).

## Reading projects

A reading project is a queryable scope over the same papers, not a container that owns them. The catalog (`user_version` 3) gains three tables: `projects(id,title,description,tags,created,modified)`, `project_papers(project_id,paper_id,position,created)` with `PRIMARY KEY(project_id,paper_id)`, and `project_archive(project_id,archived_at)`. Because the relation lives next to the papers, it is backed up, searched and exported with them, and it is reachable by the agent. A project is archived rather than deleted, exactly like a paper.

Limits are enforced before any write: 500 live projects, 2,000 papers per project, a 200-character title, a 2,000-character description, 20 tags of 50 characters, and ids matching `^p-[0-9a-f]{12}$`. An archived project is refused by every mutating action (`阅读项目 <id> 已归档；恢复后才能修改或关联`) instead of silently changing.

Authenticated browser actions (same `/api/paper-library/api` envelope; all are also admitted by the Node bridge allowlist):

- `project_create` with `title,description?,tags?` → `{project,created:true}`.
- `project_get` with `id,include_archived?` → `{project,papers,total}`; `papers` are `{id,title,citekey,year,archived,position}` ordered by the stored position.
- `project_list` with `query?,include_archived?,limit?,offset?` → `{projects,total,limit,offset}`; each entry is `{id,title,description,tags,created,modified,archived,paper_count}`, newest first. Archived projects are excluded unless `include_archived` is true.
- `project_update` with `id,title?,description?,tags?` → `{project}`. Omitted fields keep their stored value.
- `project_archive` / `project_restore` with `id` → `{project}` with `archived` reflecting the new state.
- `project_link` with `id,paper_id,position?` → `{project,linked,duplicate}`. Linking an already-linked paper reports `linked:false,duplicate:true` rather than failing; the paper must exist in the active library.
- `project_unlink` with `id,paper_id` → `{project,unlinked}`; unlinking something that was not linked is a no-op, not an error.
- `project_for_paper` with `paper_id` → `{projects,total}` for the *active* projects this paper belongs to.

`resource_list` accepts an optional `project` filter, which restricts the result to `kind='paper'` members of that project and composes with `query`, `sort`, `order`, paging and `archived`. An unknown project id is an error rather than an unfiltered listing. 画板关联通过整板 `board_save` 与 `expected_revision` 保存，`links` 可含 `papers`（最多 50）、`projects`（最多 20）、`slides`（最多 20）三个 ID 数组，summary 增加 `linked_slides`。关联侧栏复用 `resource_list`、`project_list`、`catalog_resource_list` 检索与分页，每页 20 条；论文查询活动目录，阅读项目包含归档。点击候选只选中，明确关联／解除才修改；目标删除后保留 ID 以便解除，不阻断画板保存。可读源文件同样支持顶层 `slides` 数组往返；关联和解除不复制或修改目标与画板内容。

## PlainDeck PPTX export

`slides_export_pptx` 接受 `{ "action": "slides_export_pptx", "id": "pd-…" }`。可传入 `expected_revision` 核对已保存版本，版本不一致返回 `STATE_CONFLICT`。先用 `slides_list` 获取项目 ID，或用 `slides_get` 获取其当前修订。

## Literature whiteboard

Boards are host-owned records in the plugin's private state store, keyed `board:<id>`, so they inherit the same 256 KiB record cap, revision-checked writes and atomic replacement as every other record. A board holds `{schema:1,id,title,origin,status,view,nodes,edges}` with node kinds `text|note|concept|paper|rect|ellipse|diamond`, edge kinds `arrow|line|elbow` and relations `related|supports|contradicts|cites|explains|extends`. An edge may carry `angle`: the incidence at which the drawn line meets the side it lands on, an integer from 30 to 90 (90 is the perpendicular default and is omitted from the record), which is what keeps an arrowhead from running along the node it points at. Bounds are enforced before any write: 400 nodes, 800 edges, 2,000 characters of node text, coordinates within ±1e6 and zoom 0.2–4. Listing reads a bounded window of at most 50 records and reports `{boards,scanned,total,truncated}`; a larger archive is stated, never presented as complete. Deleting tombstones the record (`{deleted:true,deleted_at}`) so it stays recoverable by hand.

Authenticated browser actions (all served by the same `/api/paper-library/api` envelope):

- `board_list` → `{boards,scanned,total,truncated}` with per-board `{id,title,origin,status,created_at,updated_at,node_count,edge_count,paper_count,ai_node_count,ai_edge_count}`.
- `board_get` with `id` → `{board,revision,outline}`; `outline` is the deterministic bounded text rendering (≤24,000 characters, stating any truncation).
- `board_create` with `board` → `{board,revision,summary}`; the host assigns the id and timestamps.
- `board_save` with `id,board,expected_revision` → `{board,revision,summary}`. A stale revision is a 409 `STATE_CONFLICT` with the current record, never an overwrite.
- `board_delete` with `id,expected_revision` → `{id,deleted,revision}`.
- `board_accept` with `id,expected_revision,item_ids?` → `{board,revision,summary,accepted}`. Reader-only.
- `board_snapshot` with `id,max_characters?` (500–24,000) → `{snapshot_id,board_id,board_title,board_updated_at,characters,truncated,omitted,text,frozen_at,label}`. The snapshot is content-addressed (its id is the SHA-256 of its own content) and immutable: editing or deleting the board never rewrites it.
- `board_snapshot_get` with `snapshot_id` → the same record, re-verified by recomputing the digest. Reader-only; a tampered record is refused.

Provenance is decided by the caller, never by the payload: a browser request is always a reader write, and the agent tool is always a model write. A model write marks only the nodes and edges that differ from the stored board as `origin:'llm'`, so an agent editing one node cannot relabel the reader's own work; a board the agent creates stays `status:'needs-review'` until the reader saves it. Only `board_accept` converts proposals into reader content, and only the reader may call it.

The readable source pair also has a Mermaid door: `web/board-mermaid.js` turns a pasted `flowchart`/`graph` into that same source document (`{source,direction,layout,warnings,counts}`, warnings carrying a line number) and writes a board back out as `flowchart` text. It is a bounded parser rather than the `mermaid` package — the plugin adds no runtime dependency — so styling and interaction directives are ignored, `subgraph` is flattened and the approximations are reported rather than applied silently. The whiteboard toolbar's 「Mermaid」 button drives it through the normal source dialog, and the asset must be listed in the plugin's static allowlist (`src/http.mjs`), copied by `scripts/build-site.mjs` **and referenced by `site/index.html`** — the third step was missing once, so the standalone entry was dead while the file answered 200. `scripts/validate.mjs` now checks all three together (`web_asset_wiring`).

A conversation reference is a token `[[paper-library-board:v1:<boardId>:<snapshotHash>]]` inserted by the plugin's own `@` source (`paper-library-boards`, order 30) next to the annotation source. At `agent/pre-step` the host replaces the token with `〔引用画板 <title>〕` and appends the frozen outline as a separate user message whose source is `{kind:'plugin',plugin:'Paper Library',paperLibraryBoard:{version:1,board_id,board_title,snapshot_id,characters,truncated,body_hash}}`. At most four board groups and the shared 24,000-character budget apply; an unresolvable, mismatched or malformed reference fails the turn instead of sending anything else. Unlike annotation snapshots, a board snapshot is not bound to a paper conversation, because a board is cross-paper by nature.

## Native paper conversations

The authenticated Harness HTTP carrier routes `chat_*` requests to `options.paperChat(input,{signal})`, separate from the generic Node `dispatch`. Standalone HTTP returns an explicit unavailable error for these operations. Browser requests cannot select a deployment directory, submit an arbitrary native Session ID for sending, or provide the text to be saved as an AI reply.

Every operation requires the catalog paper `id`. A stable native Session ID is derived from the canonical library directory and paper ID; distinct papers and libraries remain separate. Opening a paper creates its Session on demand through `sessions.prepare` and the public `sessionPersistence` handle, then attaches it to the library Workspace. The Session remains cold: no Agent or model request starts. Importing a batch does not create Sessions. Persistence failures propagate; only a definite absence permits recreation under the same identity. Archived Sessions return an error and are not replaced. Moving a library directory currently changes the derived identity.

After the first log is flushed and its handle closed, the adapter optionally calls public `sessionProjectionCache.write(prepared)` so native lists can read the durable title and blank-state hints without loading the Session. A cache failure is nonfatal. This does not change Harness's zero-turn semantics: noncurrent empty Sessions are hidden, the selected empty Session displays “New Session”, and its main header stays hidden until the first prompt. “Open main conversation” can select the stored identity throughout. The plugin does not manufacture a turn to change those native UI rules.

`source_session_id?` may identify the current Harness conversation during first creation. The adapter reads only that live Session's public model projection, taking its pending selection or last-used route; without one it uses `agentDefaultModel.currentSelection()`. The choice is persisted once as `model/selection` before Agent activation. Reusing the paper Session preserves its own selection. The adapter never calls `selectModel` or changes the global default; caller-supplied `provider` and `model` do not override native routing.

|---|---|---|
| `chat_ensure` | `source_session_id?` | `{sessionId,created,title,model?,modelSource:'harness-session'}` |
| `chat_catalog` | No additional input | Session/catalog fields plus `{annotations,pending_count,annotation_usage,usage_revision,usage_truncated,limits}`; each annotation adds `status:'new'|'updated'|'sent'` |

`chat_context` accepts up to 1,000 distinct `annotation_refs:[{id,version}]`, a question of at most 4,000 characters and a selection of at most 8,000 characters with a real one-based page inside the attached PDF. The source-character budget includes full annotation text, comments and selection, counting Unicode code points. `maxAnnotationCharacters` defaults to 24,000 and is deployment-configurable from 1,000 through 96,000. Browser inputs cannot change that budget. Over-budget content is rejected; reduce the selection or submit separate questions. No automatic batching or summary synthesis is performed.

The version-aware `annotation_refs` input takes precedence over legacy `annotation_ids`. An explicit empty list omits saved annotations. If both fields are omitted, the adapter selects all available current user annotations, but refuses an incomplete catalog. Legacy IDs are resolved to current versions once during initial preparation. The UI always sends explicit versions. Missing or changed versions require the user to remove the entry or adopt its current version. A request must contain a question, selection or annotation. Source text is quoted as untrusted data with the paper title, citation key, real pages and annotation identifiers; preparing it does not supply the whole PDF.

The frozen-reference result is `{sessionId,snapshot_id,reference:{ref,label,clipboardText},text,draft_text,annotation_ids,annotation_refs,context_hash,coverage}`. Both `ref` and `clipboardText` are `[[paper-library-ref:v1:<paperId>:<64hexSnapshotId>]]`. `text` is a readable source-and-question preview; `draft_text` carries that token plus the frozen question for native submission. `annotation_refs` also includes each actual page. Coverage retains `{requested,included,total,total_exact,all}` and adds `{selected,characters,max_characters}`. No source bodies are stored in browser selection state.

Immutable snapshots live in the configured library's `.paper-library/snapshots/`, and logical request bindings live in `.paper-library/requests/`. Directories are private `0700`, files `0600`; a snapshot record is capped at 1 MiB and its formatted source text at 200 KiB. Content-addressed publication never overwrites an existing snapshot. Loading checks the hash, configured library identity, paper and Session; tokens cannot choose arbitrary paths. Snapshots preserve sent material while standard PDF objects remain the mutable annotation authority.

`chat_send` uses `sessionController.prompt(...,mode:'queue')`. Each paper's operations are serialized, with at most 32 admitted adapter requests. A logical `request_id` is durably bound to its first snapshot; retry with that same ID and `snapshot_id` to preserve the actual materials and question. Reusing the request with a different snapshot fails. Changed materials or a changed question require a new logical request. Harness deduplicates its derived native request identity. Acceptance means the message entered the queue, not that an answer completed or that its reference baseline advanced. Tool use, permission requests, cancellation and model selection continue through Harness's normal conversation controls.

On the public `agent/pre-step` waterfall, the plugin awaits `next()` and preserves rejection. Explicit direct-user tokens are loaded from immutable disk snapshots without PDF or model work. The resolver replaces each token with a readable batch label and appends a real native user-role context message containing the exact source text. Its source is `{kind:'plugin',plugin:'Paper Library',paperLibraryReference:{version:1,paperId,sessionId,snapshot_id,annotation_refs,body_hash}}`. Version hashes and snapshot IDs stay in this logged metadata rather than the model-facing text. At most four groups are resolved per step, with a shared source-character budget across incoming messages. Wrong-paper, wrong-session, missing or malformed references fail explicitly.

`paperLibraryAnnotationUsage` is a pure native Session projection. It checks the producer, Session and source-body hash on actual `user/message` events. Plain tokens, queued messages and AI text do not advance it. Before returning an activated Session's usage, the adapter requires successful durable flush. The projection holds at most 5,000 annotation identities, replacing their last explicitly cited versions; eviction sets `usage_truncated:true`. Evicted entries may appear pending again, so consumers must not claim complete usage history when this flag is set. Ordinary history-window limits do not erase older projected usage. Usage records do not imply that the model still retains the original source after compaction.

`chat_history` reads one `follow` opening snapshot, then aborts and closes the iterator before cold-Session promotion. The read has a 20-second deadline. It returns up to 20 committed human/assistant text messages, at most 6,000 characters each and 48,000 total. Message rows use `{id,role,text,interrupted?,model?,truncated?,references?}`, where `id` is the durable event sequence as a string. Verified Paper Library context is folded into the associated inline user row; each reference is `{snapshot_id,paperId,count,pages}` and can load its full immutable preview through `chat_reference`. Unrelated system/plugin instructions, reasoning, tools and uncommitted streams remain excluded. The main Harness transcript keeps its native generic plugin-context rendering. `hasMore` reports omitted older messages; `outcome` may carry the latest native turn result such as `completed`, `error` or `aborted`. The visible inline view refreshes every four seconds and stops when hidden. Opening the main conversation or sending a prompt may activate a native Agent; the plugin does not own or dispose that Agent.

`chat_save_feedback` resolves `message_id` against this paper's current bounded native history, requires a completed, non-interrupted `assistant/message`, and reads its actual text server-side. Browser text, model labels and associations are ignored. `annotationReplySources` uses verified plugin references in the same native turn, and checks their IDs against the immutable snapshots before associating. New turns clear the association. A reply without an explicit source remains unassociated on the requested default page; prose is never parsed to guess IDs. When the generating model header is absent, its saved label states that the model is unavailable. Replies outside the history window, empty text and replies exceeding 28,000 characters reject. Full conversation history remains in Harness.

On native `turn/end` with `reason.kind:completed`, the host reconciles eligible replies without requiring a browser. A history read also recovers eligible recent replies missed while the plugin was unavailable; it writes at most two per call, newest first, and does not traverse the library or start a model. Automatic saving requires a visible turn-start boundary, verified references, a non-interrupted assistant message and a completed turn. Native session flush precedes PDF writes. Internal `paper.reply:<hash>` host state records pending/saved/failed admission; future polls never replay an uncertain/failed save or recreate a deliberately deleted saved reply. Explicit save retries use the PDF's Session/message deduplication key. Failures remain visible beside the original DSH message.

The reading rail counts source notes and nests saved AI responses under each associated note. Multi-source responses are labelled; orphan/unassociated replies remain in a separate collapsed recovery group. PDF objects are not flattened into their parent's comment. JSON preserves every association; XFDF exports the standard first-parent `inreplyto`, while Markdown lists associated IDs. Native `/IRT` requires a same-page parent, so an old cross-page unassociated note keeps its original location and stores the recovered associations in metadata. This preserves old content without moving it silently.

## Import and browser transport

`POST ./upload?filename=<encoded.pdf>` receives a raw `application/pdf` body, streams into a private temporary directory and dispatches PDF import. Maximum 250 MiB, at most two active uploads, 180-second upload/import signal. Partial and completed temporary files are removed after handling. Same-origin and host authentication rules apply before reading the body. Legacy metadata uploads remain JSON Base64, with a 45 MiB encoded HTTP body limit and 32 MiB decoded file limit. At most two JSON requests are admitted before reading their bodies; excess requests receive HTTP429. Queued imports share a conservative 96 MiB UTF-16 payload budget and 50-item cap, including non-HTTP callers.

`inspect_pdf` is an internal worker operation, rejected by browser dispatch. It returns metadata candidates and bounded evidence from at most three pages / 30,000 text characters. Inspection text is ephemeral and not persisted. `parse.needs_review` remains true for incomplete or unverified identity. DOI/arXiv text candidates alone are not bibliographic authority. `acquisition.validation:'pdf_parser'` means readable bytes; separate `metadata_identity` records title matching. Local DOI lookup receipts are retained under `acquisition.enrichment`.

Public acquisition limits: default60-second total deadline, 15seconds/request, five redirects per request, 16 requests, eight PDF candidates, 2 MiB per text response, 250 MiB PDF. All redirects and requests revalidate public DNS and pin the validated address to the socket. Credentials, nonstandard ports, private/reserved IPs and redirects into them are rejected. No proxy, browser cookie, logged-in provider or external fetch runtime is implied. Crossref, arXiv and generic citation meta tags supply candidates; HTML with a PDF filename does not pass validation.

Managed filename: `author-year-title--id8.pdf`, bounded to 210 UTF-8 bytes; collisions use the full stable id. Metadata edits use a recovery journal when renaming a managed file. Attaching a PDF to an existing metadata-only item preserves its bibliography/citekey and merges actual PDF parse, source hash and acquisition evidence. Original imported files remain unchanged.

The plugin registers `skills/paper-library-fetch/SKILL.md` as `paper-library-fetch` with Harness's scoped skill registry, both model- and user-invocable. Its tools are the existing `library_import`, `library_get`, `library_cite`, `library_annotations` and `library_feedback`. It does not install or watch a global skills directory.

The parent pane publishes version1 `paper-library:context` messages containing `sessionId,provider,model,reasoningEffort,status`. Both sides require the exact counterpart window and same origin. The frame announces `paper-library:ready`; the parent subscribes to the public model directory. This supplies first-creation context and the compatibility route, while an existing paper conversation's model remains authoritative for `chat_send`.

Appearance has a separate version1 protocol: the child sends `paper-library:request-theme`; the parent replies with `paper-library:theme` containing `{status:'ready',mode:'light'|'dark',tokens}`. Both endpoints require the exact counterpart window and same origin. `src/client/theme-context.mjs` reads the optional official `ctx.get('theme').getTheme()` snapshot and subscribes to `theme/change`. Mode comes from `active.colorScheme`, never the theme ID; valid snapshot `fontSize` supplies `--dsh-content-font-size` at 12–17 px. Built-in colors are CSS-owned, so the bridge resolves only its 38 allowlisted presentation variables from the host's computed body styles after the event is applied. The list includes DSH surface, border, label, interaction, status, scrollbar and font variables; unrelated host state never enters the message.

Values are capped at 512 characters each and reject unresolved `var()`, URL expressions and stylesheet syntax. The child additionally validates supported color/font values and replaces only tokens it previously applied. Narrow root/body style, class and theme-attribute observers cover bootstrap and typography changes, with coalesced notifications and no polling. Hiding the iframe removes the event subscription and observers; `{status:'unavailable',mode:null,tokens:{}}` retracts inherited tokens. `web/theme.js` then follows the system color scheme, as it does in standalone mode. It writes no browser or host preference. `web/theme.css` maps controls to DSH semantic variables; PDF image pixels and annotation colors are not filtered.

The version1 `paper-library:conversation-action` / `paper-library:conversation-result` exchange handles explicit `open`, `draft` and list `refresh`. The parent accepts only registered same-origin frames. A reference draft carries `sessionId,text,draft_text,reference,snapshot_id`; the parent appends `draft_text`, then turns its canonical token into an official `paper-library-annotations` input reference using the target Session's scoped event and revision-guarded TokenSpan. Existing text, references and attachments remain intact. Busy or blocked composers refuse the edit and retain the draft. A refused chip decoration retains a sendable canonical text token. No prompt is sent by preparing a draft.

The reference codec serializes the same token. Harness persists a string draft, so reload currently restores ordinary text; a dock inspector still permits on-demand preview and page navigation. The plugin does not claim automatic chip reconstruction. The inspector uses additive `conversation.input.dock`; it does not replace the main input or history renderers. Authenticated parent `paper-library:reference-open` messages carry `{paperId,page,snapshot_id}` to reveal the source in the reader. A transient parent-frame handoff retains `{paperId,page,tab,chatDraft,chatContext:{annotationRefs:[{id,version}],selection?},annotationDraft?}` within 256 KiB, excluding PDF images. Host-owned per-paper records are authoritative after reload; an older parent handoff cannot overwrite a stored chat draft. No credentials cross these protocols.

UI relative base: embedded Harness `/api/paper-library/` POST `api` or `upload`; standalone `/` with the same relative routes. Download GET `pdf/<encoded item id>`. Static assets include `app.js,paper-chat.js,paper-markdown.js,workbench.js,knowledge-graph.js,pdf-reader.js,reading-panels.js,reading-shell.js,local-state.js,language-learning.js,theme.js`, local styles including `theme.css`, and `index.html`. Metadata and chat drafts use separate host-owned records per library/paper. The working set is bounded; older durable drafts are not evicted. An oversized current form stays visible rather than being replaced by another draft.

## Live reading companion

The native web host advertises `status.realtime_companion:true`. It reuses the revisioned `auto-paper-conversation` setting (new installs default false). After a successful HTTP `annotate` or `annotation_update`, the host admits a job for a human annotation with a nonempty comment. The response retains the saved annotation and adds `companion:{status,...}`; a queue failure never reports that the PDF save itself failed. `companion_skip:true` is used by the explicit save-to-composer action, which remains draft-only. Model tools, raw highlight saves, AI annotations and unchanged versions do not admit work. Clearing a comment withdraws its queued/preparing job; submitted turns remain under DSH control.

`companion.queue:v1` holds at most 200 pending jobs in the existing host store. `companion.paper:<hash>` holds the latest status for at most 100 note identities per paper; it is a UI projection, not annotation/reply authority. A fingerprint versions the saved note's semantic content and geometry. Unsent changes to the same note debounce for 1.8 seconds. A single host queue submits the next automatic question only after the preceding reply is saved or explicitly failed, preventing native inbox batching from merging a burst of separate notes. This is a single-service queue, not a distributed scheduler.

Each job resolves the current exact annotation version and freezes it through `chat_context`, adding a bounded text excerpt from its one physical page (7,000 characters; truncation stated, no image/OCR interpretation). The companion prompt is an independent continuous-reading adaptation: answer the current comment, separate source/reader/inference, give proportionate explanation and leave an optional delayed verification question. It does not invoke the user's private skill, mutate external learning ledgers or claim mastery. The normal paper Session/model receives the prompt with the same snapshot and idempotent native request mechanisms as manual questions. Native approvals, stop controls and model tools remain DSH-owned; the companion prompt is not a tool sandbox.

- `companion_ask {id,annotation_id,version?}` explicitly queues a reply for one saved human annotation with a comment or selected text. The host reads the current annotation, checks the version if supplied, and records its version for execution. It reuses an existing request for the same version. An explicit request can run while automatic companion mode is off. The model reply uses the same native PDF feedback and source-annotation link.
- `companion_status {id}` returns `{enabled,entries}` with queued/preparing/sending/accepted/saved/failed/cancelled/superseded state, annotation/request/snapshot identities and bounded error text. A read reconciles missed native feedback for this paper without generating.
- `companion_retry {id,request_id}` explicitly recovers an uncertain admission with the original native request and snapshot. A confirmed stopped/idle unresolved turn requires a new request identity but preserves the original source snapshot. If a native answer exists and only PDF saving failed, retry calls `chat_save_feedback` without a new model request.
- `companion_cancel {id,request_id}` withdraws queued or failed work. Submitted generation must be stopped in the native main conversation.

On restart, only sessions already named by durable accepted/sending records are reconciled. Unstarted queued entries resume; uncertain preparation or generation is not automatically replayed. No catalog scan or per-paper watcher runs. Turning off the setting pauses unsubmitted automatic work. The browser shows status beneath the source note and polls only its current pending work, stopping when hidden. The host owns queue execution across browser lifetimes.

Native `/IRT` replies with the explicit external subject `AI 伴学回复` are recognized as generated feedback while retaining `source:external-pdf`; author names and body wording alone never classify AI. Existing replies are preserved and excluded from new human-source selection. No WPS/external-editor save watcher, automatic old-note backfill or standalone-to-DSH proxy is included. `companion_excerpt` is an internal worker action and is blocked at the browser HTTP action boundary.

## Durable local state

`createLocalStateStore({library,home?})` resolves the same home as DSH (`home` override, `DSH_HOME`, then `~/.dsh`). The official `dsh-home-paths` and `dsh-atomic-write` utilities are optional runtime peers; standalone fallbacks preserve path and lock semantics. Files live below `paper-library/<sha256(canonical-library-path)>/state`, with private directory/file modes 0700/0600. Replacement writes sync the file before rename and sync the directory; cross-process locks and compare-and-swap versions reject stale writers. This is plugin-owned durable data, not a Session event format or a disposable cache. Existing library and native Session locations remain unchanged.

- `state_get {key}` → `{key,value,revision,updated_at}`; missing values have `value:null,revision:0`.
- `state_put {key,value,expected_revision}` → the committed record. Revision is 0 for absence or an opaque 64-hex version; it is never a numeric counter. Writes above 256 KiB, invalid JSON, unsafe paths and corrupt existing records are rejected without erasing the existing file.
- `state_list {prefix,offset=0,limit=20}` → `{records,total,offset,limit,next_offset,hasMore,truncated}`; at most 50 records and 8 MiB per response.

Browser-addressable keys are `preferences`, `reader`, `reader:<paper>`, `chat:<paper>`, `metadata:<paper-or-new>`, `language-draft:<paper>` and `migration:<sha256>`. Language result and vocabulary records are written only through their service below. HTTP state actions retain authentication, same-origin and no-store policies. `STATE_CONFLICT` returns HTTP409 and the current version; the UI keeps local pending text, displays a persistent recovery banner and offers JSON export. It never resolves conflicts by silently replacing the host version. Ordinary network failures can be retried; a lost write response is read back before deciding whether it already committed.

`local-state.js` migrates only known legacy Paper Library localStorage keys. Removal follows verified host storage. Conflicting legacy versions become separate host backup records, downloadable as old drafts; malformed or oversized data remains explicitly unresolved. No new browser-storage content is written. Each browser holds a bounded working set, flushing edits during use and attempting keepalive on page exit; an unsaved/error indicator must not be read as durable confirmation.

## Translation, expression improvement and vocabulary

`language_generate {id,mode:'translate'|'polish',text,page?,target_language:'auto'|'zh-CN'|'en',request_id}` 接受最多 8,000 个原文字符。新界面默认跟随共享语言设置；自动识别中文正文时译为英文，否则译为中文，也可固定方向。识别只对有界选文做文字特征判断，并跳过常见 LaTeX 标记、引用与数学，不额外调用模型。旧客户端省略参数仍按中文处理，以保留历史请求重放；润色保留原文语言、含义、不确定性和证据强度，服务将其目标语言规范为 `source`。原文按引用数据处理。新请求默认采用 DSH 当前默认模型；有语言工具专属设置时使用该覆盖，不读取论文会话模型，也不改变宿主默认或论文会话选择。模型路由来自服务端设置及 DSH 当前可用模型目录，`language_generate` 请求中的任意模型字段不能覆盖它。输出预算为 `maxLanguageOutputTokens`（默认 8,192，范围 256–16,384），与批注回复预算独立；最多同时生成 2 个请求，每次限时 120 秒。

新生成的完整结果包含 `{id,request_id,paper_id,page,mode,target_language,source_text,result,explanation,model,model_source,prompt_version,created_at,generated_at,completed_at,vocabulary,status:'complete',replayed}`；`model_source` 为 `harness-default` 或 `language-override`；`target_language` 是实际译文语言，自动方向另保留 `requested_target_language:'auto'`，恢复未完成请求时保持该方向与原请求身份。提示词要求最多 12 个难词，保留的词条和原句必须确实出现在输入中。只有完整且通过结构校验的输出才进入完成流程；先保存结果，再合并难词，后续落盘失败可复用结果继续。完成后的同一 `request_id` 重放返回原结果且不再次调用模型；改变语言设置不会重做旧请求，重新生成需新的 `request_id`。`LANGUAGE_FAILED` 允许明确新建请求，`LANGUAGE_PENDING` 保留不确定请求身份，`LANGUAGE_COMMIT_RETRY` 继续保存已有合格输出。界面显示这些状态，不自动发起另一次付费调用。

- `annotation_translate {id, annotation_id, version, retry?}` 翻译一条完整批注并写为 PDF 回复，返回 `{saved, duplicate, annotation}`。版本来自 `annotations` 返回的短批注；缺少版本、来源已改变或来源超过 8000 字符时拒绝生成／写回。目标语言和模型复用语言设置，不接受客户端传入译文。每次明确调用可恢复已确认失败的旧语言请求，刷新后无需额外的重试标志；本次刚失败或状态不明的请求不自动连发，已生成结果继续复用。页码按当前 PDF 页树核验，不依赖目录中的 `page_count` 缓存。
- 标准 PDF 回复的 `source_kind` 为 `annotation-translation`，正文以「翻译：」开头，带模型标识、原生回复关系与去重键。内部 `annotation_translation_result` 只供宿主适配器调用，HTTP 直调拒绝。保存时持有同一资料库锁重新核对来源版本，再备份并原子替换 PDF。
- `language_settings_get {}` 返回 `{value:{model,target_language,translate_prompt,polish_prompt},revision,models,default_model,translation_default_model}`。`model:null` 表示翻译优先已配置的轻量路线、润色沿用 DSH 默认模型；轻量路线依次为 deepseek-official/deepseek-flash（off）、kimi-coding/kimi-for-coding-highspeed（low）、deepseek-account/deepseek-flash（off），没有这些模型时回退宿主；不自动跨模型重试失败请求。`translation_default_model` 返回自动翻译的实际候选，显式语言模型始终优先。`default_model` 是读取时的默认选择，未配置或当前无法读取时为 `null`；`models` 是当前可用目录。设置保存在当前资料库对应的主机状态中，所有论文共用，不按论文会话选择模型。目标语言缺省为 `auto`；旧客户端更新时省略该字段会保留已有值，设置修订冲突不覆盖输入。
- `language_settings_update {value:{model:null|{provider,model,reasoningEffort?},target_language?:'auto'|'zh-CN'|'en',translate_prompt,polish_prompt},expected_revision}` 返回 `{value,revision}`。指定模型必须存在于 DSH 当前可用目录；生成前也会复核，失效时返回 `LANGUAGE_MODEL_UNAVAILABLE`。修订冲突沿用 `STATE_CONFLICT`，保留待保存设置并重新读取。`translate_prompt` 与 `polish_prompt` 分别用于翻译和润色，每项最多 2,000 字符，首尾空白会去除；它们作为用户风格要求加入提示，不得覆盖忠于原文及结构化输出要求。实际模型和所用补充提示词版本随新结果保存；未设置默认模型且无专属覆盖时返回 `LANGUAGE_MODEL_REQUIRED`。
- `language_history {id,offset=0,limit=20}` returns paginated records, including explicitly pending/failed states. Looking at history does not call a model.
- `vocabulary_list {query?,sort?:'id'|'term_asc'|'term_desc'|'created_desc'|'created_asc'|'updated_desc',status?:'learning'|'mastered',offset=0,limit=20}` returns terms with revision, meaning, learning status, AI suggestion/meaning provenance and recent source encounters. Limits are explicit; the history retains the full generated result.
- `vocabulary_update {id,meaning?,status?,expected_revision}` retains user corrections and mastery across later encounters. `vocabulary_delete {id,expected_revision}` preserves a deletion marker so later automatic accumulation does not immediately re-add a deliberately removed term.
- `vocabulary_export {format:'json'|'csv',query?,status?}` returns `{filename,mime_type,content,count,truncated}`; export is bounded to 2,000 words / 8 MiB and CSV neutralizes spreadsheet formula prefixes.

Records and word review remain available in standalone mode using the same local files. Generating requires the installed DSH integration. Opening panels, browsing words or reading history starts neither PDF scans nor a model. Language results can be copied or appended to the correct paper's existing conversation draft; they are not automatically sent to the conversation or written into the PDF.

## Selected-paper background analysis

`status.paper_analysis` 表示当前服务已接入生成入口。DSH 入口使用原生 `subagents`／Agent 与工具守卫，模型来自论文 Session；独立服务通过 `--model-config` 接入显式 GLM／Kimi 配置，无需 DSH。请求体不能覆盖模型路由。`paper_analysis_records` 在不配置模型的独立服务中也可用。下述原生 Agent／自动队列说明仅适用于 DSH；独立调用的预算与中断规则见[无界面分析](headless-analysis.md)。

独立入口 `createHeadlessAnalysis` 和 CLI 另支持 `paper_analysis_run {ids:[...],request_id,mode?,pages?,notes?,review?,apply_metadata?,input_format?,include_images?,question_ids?,question_mode?}`（单篇可用 `id`）。最多 2000 个唯一 ID；调用等待整批完成，返回 `{status,counts,results,reused,usage,usage_scope:"headless_instance"}`。结果保留逐篇派生请求 ID、覆盖范围、草稿引用及失败信息。相同批次请求复用；变更选择、选项、模型或预算报冲突。模型配置只接受指定提供方、型号、凭据变量名及可选凭据文件，密钥不进入持久作业或输出。

共享单篇内核新增 `mode:"full"|"metadata"`、`notes:boolean`。独立入口默认 `full`、`notes:true`、`review:false`、`apply_metadata:false`；`metadata` 默认第 1 页且不生成精读笔记或评审，只保存有原文出处的字段建议与 `mode:note` 待审阅资料笔记。显式 `pages` 可扩展范围。已保存的旧请求保持原有请求指纹，只读复用。新建 full 作业统一使用问题阅读协议，不再提取或写回元数据；即使旧客户端传 apply_metadata:true 也不生效。HTTP `start` 立即返回，CLI `start` 等待完成；CLI 部分失败保留 JSON 并非零退出。

Earlier committed batches remain usable if a later batch fails. No Session activation/send. |

新协议的结果包含 `questionnaire:{version,hash,groups}`、`question_coverage`（每题 expected_batches/answered_batches/failed_batches/unread_batches）、`analysis_complete` 与 `question_summary`。`batch_index` 可查看 `batch_answers`、`question_results`、`batch_compilation` 和 `option_candidates`。`include_raw:true` 读取该批已保存的模型返回；中途停止的题组在 `active_questions`，保存中断会显式报告 `missing_parts` / `raw_complete:false`。没有覆盖的页面、未完成的问题和仅覆盖部分材料的笔记不会计为完整分析。全部通过仍只是结构和来源检查，不是人工语义核验。

传入 `paper_analysis_get.batch_index` 时，`batch_metadata` 和 `batch_field_sources` 返回该批已保存的资料建议及原文依据；`metadata` 与 `field_sources` 仍是整个作业累计的首个支持值。读取历史批次不重新生成、提取或修改作业，不能把累计建议误认作某一批的全部输出。

Default extraction visits every PDF page in bounded batches using the existing text path (`input_format:"text"`, `include_images:false`). Explicit `input_format:"markdown"` uses pinned `pymupdf4llm` and keeps raw page text plus normalized Markdown in the private derived cache. Markdown-source quotes are exact against that saved Markdown, not a claim of verbatim PDF transcription. Explicit `include_images:true` is supported by the standalone GLM/Kimi adapter only: at most two page images per batch, each at most 1 MiB and 1600 pixels on the long edge, transmitted separately with its page number. Native DSH explicitly rejects image input. No OCR is performed, and scan-only visual reading is not separately supported. Explicit selection supports up to 2,000 unique page numbers. A worker invocation accesses at most eight pages and returns at most eight source chunks / 24,000 Unicode characters, with at most 8,000 characters per chunk. A page-index/character-offset cursor continues dense pages without discarding their remaining text. File size and string-valued nanosecond modification time fence later batches against PDF edits. Immutable knowledge sources use `source-note` with page, character range and trusted extraction provenance. Coverage names requested/read/completed/blank pages; `full_document:true` means all pages' extractable text was processed without omissions or blank pages. It does not establish coverage of figures, scanned text or OCR.

不同论文按部署的 `analysisConcurrency`（1–4，默认 2）并行；同篇的文字批次和问题顺序执行。新建全文作业采用 `reading-questions-v4` 的 23 题，每批默认逐题调用，可设置 `question_ids` 子集；`grouped` 按冻结题库分组，v4 也为单题。旧 v1/v2/v3 记录保留原题与分组，不因升级重放。模型每次只见当前文字批次，不传目录元数据、不要求生成图谱 JSON。程序校验回答、定位原文并编译图谱；图谱最多 80 个节点、160 条结构边、80 条证据关系，超限的整个回答保持在问题记录中并显式报告未投影。单题失败不阻断其他问题与后续页面，显式调用额度耗尽仍停止。没有跨批次图谱合并。实际提示、选择项和边界见[阅读问题协议](reading-questions.md)。

原生 DSH 复用宿主 LLM 路由进行无工具的单次调用，不依赖旧版子代理接口，不进入论文主对话；保留 120 秒调用时限和完整响应检查。独立后端沿用显式 API 凭据与预算。宿主接口不可用、模型配置缺失或不支持图像时立即停止，不逐题重复相同错误。

`paper_analysis_resume` 接收 `{id,request_id?,new_request_id?}`，继续同篇已停止的逐题任务；省略 `request_id` 时使用最新记录。客户端应提供稳定的 `new_request_id` 以便重试去重。范围、题库、模型和来源保持原任务约束；完整回答按提示及来源身份校验后复用，不完整请求才重新调用。已完整保存的批次复用图谱草稿，原任务记录保留。来源或题库改变时拒绝恢复，需明确重新整理。同一篇文献不能同时运行多个分析任务。详见[继续中断任务](reading-questions.md#继续中断任务)。

Durable `analysis.job:*`, `analysis.latest:*`, `analysis.batch:*`, `analysis.question:*` and `analysis.queue:v1` records live under the DSH-home state namespace, inaccessible through browser `state_*` keys. Import/attachment events and explicit selection admit only those paper PDFs; metadata-only records and datasets do not enter the queue. The queue holds at most 2,000 identifiers / 200,000 serialized bytes; overflow is surfaced without undoing the import. One host drains the queue with the same bounded parallelism as manual starts, continues after the browser closes, and resumes unstarted entries on startup without searching the catalog. Turning automation off pauses pending items; running work can be cancelled explicitly. Interrupted, failed or cancelled jobs are never automatically replayed. Full reading never fills metadata; explicit metadata-mode jobs retain their separate fill setting.

`knowledge-draft:analysis:<paper>` page/batch/node-selection drafts use the same host file store; analysis preferences use the shared settings contract below. Job states are queued/reading/generating/committing/complete/partial/failed/cancelled; running records without an owned flight appear interrupted after restart. Reading or restoring saved results never reissues a model call. There is no cross-process job scheduler or whole-library discovery scan.

A completed run also saves one reviewable **reading-note draft** (`mode:note`): after the last batch commits, the same tool-free host model call condenses the committed batch graphs — not the raw PDF a second time — into a structured Chinese note (一句话概括 through 待核实与未覆盖), using the paper's authoritative model. Prompt material is the bounded per-batch draft projection (at most 24,000 bytes, batches included in order; partial coverage is recorded as `note_coverage` and stated in the note). The draft's sources are the snapshots actually quoted by the included batches, bounded by the knowledge source budget; batch records retain complete per-batch source lists. The note draft is always `needs-review`. A failure preserves question answers and adds a warning; new questionnaire jobs become `partial`. Material outside the persisted source budget is excluded from both the prompt and citations, and partial note coverage prevents `analysis_complete:true`.

A completed run also saves one reviewable **evidence-atlas review draft** (`mode:note`, title prefixed 证据图谱评审) when `review` is not `false`: the same tool-free host model call applies the bundled `paper-library-review` method to the same bounded batch projection — case splitting with eight-dimension coding, attribution (author_claim / reported_result / reviewer_inference), structured absence, joint-coverage anti-stitching, adjective operationalization, per-requirement status, and a P0/P1/P2 revision list. The body must contain every required section (快速判定 / 案例拆解 / 状态矩阵 / 归因 / 联合覆盖 / 形容词 / 本文最多能声称 / 本文不能声称 / 修改清单) and stay within 64,000 bytes; a report missing a section is refused and only leaves a warning. `review_coverage` records batches, sources and partiality; `review_profile` records the configured private overlay path, its character count, whether it was truncated at 8,000 characters, or a read error. The draft is always `needs-review`; a failed or partial requested review leaves new questionnaire jobs `partial`, preserving completed answers.

`reviewProfile` is a deployment-owned **absolute file path** (optional, in the plugin config, never in a request body): when set, the plugin reads that local Markdown once per review generation and injects it as a labelled `PERSONAL_REVIEW_OVERLAY` block. It is never discovered, never bundled and never written back; a missing or unreadable file only removes the overlay for that run.

Internal worker actions `paper_analysis_batch`, the legacy `paper_analysis_sources`, and `paper_analysis_apply_metadata` are blocked at browser HTTP and are not model tools. Fill-only metadata writes after successful analysis reuse the managed-PDF backup/atomic-write path and CAS inside the existing paper lock. Proposed DOI/citekey/JCR changes are forbidden; citations retain their identities. Every filled field retains exact selected-source quotes and `origin:llm, review_status:needs-review`. Context preparation retains that review distinction, writes only a selected paper's draft and requires an explicit later send.

## Canonical bibliography build

`bibliography_build` writes `exports/references.bib` and `exports/bibliography.audit.json` inside the managed library directory, using atomic replacement. It is available as the browser action (the workbench shelf button), the `library_bibliography` native tool, and the JSON CLI. Catalog records and managed PDFs are never modified; the audit reads metadata and stats PDF paths without opening files.

| Field | Contract |
| --- | --- |
| `include_datasets` | Default `true` exports the unified catalog (papers, datasets, releases); `false` restricts the BibLaTeX text to papers. The identity audit always covers exactly the active paper catalog. |
| `verify` | Default `false`. When `true`, up to `verify_limit` (1–100, default 25) paper DOIs are resolved through the bounded public metadata path and compared field by field: `title`, `year`, `container-title` and `first-author` each report `validation_status` as `match`, `conflict` (both stored and registered values recorded), `missing-catalog`, `missing-online` or `missing-both`. A record is `provider-confirmed` when no field conflicts, `conflict` when any does, or `unavailable` when the registration cannot be fetched or answers a different DOI. Each verified record carries `checked_at` and the registry `source` host. Nothing is written back to the catalog. Remaining unverified records are reported as `remaining` with `truncated:true`. |
| Result | `{count, kind, bib_path, bib_bytes, audit_path, audit_bytes, conflicts, doi_duplicates, missing, actionable, pdf_missing, verification, warnings}`. |

The audit (`paper-library-bibliography-audit.v1`) reports totals, per-field missing identity lists (citekey, DOI, title, author, year), citekey conflicts, duplicate DOI groups and managed-PDF file presence, each capped at 200 listed identifiers with a `truncated` flag; up to 10,000 records are audited. `actionable` splits DOI-missing records into `lookup_by_url` (a landing URL remains, so the existing metadata-lookup path applies) and `manual_only` (no identifier and no URL), and each record carries `has_url`. BibLaTeX text is capped at 24 MiB and the audit at 4 MiB. An empty library rejects instead of writing empty exports. BibLaTeX remains citation metadata only: files, usage links and knowledge records are outside its scope.

## Shared settings

`settings_get` returns `{namespace, backend, available, writable, revision, value, base, user, native_revision}`. The namespace is `paper-library`. The HTTP revision is an opaque 64-character digest; it is distinct from the numeric revision used by DSH's native settings scope.

`ui_palette` 为 `jade`（默认墨绿铜金）、`navy`（深海蓝灰）或 `system`（跟随 DSH），由同一设置接口保存；非法值拒绝写入。功能色、明暗模式与 PDF 原色的关系见 [设置](../README.md#设置)。

`settings_update` 接收 `{patch, expected_revision}`；`settings_reset` 接收 `{expected_revision}`。可编辑项包括阅读自动化与侧栏偏好、`sync_config`／`external_sources` 外部源配置，以及 `latex_*` 工作台偏好；完整字段、默认值及校验以 [settings.mjs](../src/harness/settings.mjs) 为准。更新只覆盖提交的字段；未知字段和过期修订在写入前拒绝。HTTP 恢复默认会清除全部这些用户覆盖，包括外部源与 LaTeX 偏好，因此新原生阅读设置页不展示该重置按钮。模型、凭据与执行权限不通过此接口设置；语言模型及提示词使用独立的语言设置接口。

With the native provider, updates call `ctx.settings.update/mutate` and use its persistence, change events and revision fences. The old `state_get/state_put` interface for `preferences` projects these four fields from the same native namespace; other state records keep their original storage contract. First migration retains the old record, a private backup and a migration receipt. Explicit native values take precedence and reset fields are never reimported.

当前原生客户端通过公开的 `settings.section` 注册左侧 Paper Library，阅读偏好复用 `settings_get/update` 的主机读写与 CAS；语言区域复用 `language_settings_get/update`，与插件内语言设置共享值和修订号。重开时仅在没有未保存草稿时刷新，冲突保留当前输入，显式重新读取才放弃输入。旧宿主提供 `settingsScope` 时仍保留 `settings.plugin.item` 卡片及其失效通知桥；左侧入口不依赖该可选服务。可见阅读 iframe 只接收命名空间／修订号失效通知，插件内设置在打开、聚焦和通知时刷新，显示期间每三秒核对一次，关闭后停止。读取设置不读取目录、PDF 或调用模型。

An independent deployment without a DSH migration marker uses local disk preferences. A standalone service sharing a migrated library reports `{backend:"dsh", available:false, writable:false, value:null}` and refuses preferences writes until opened through DSH. It does not open a second settings-file provider or mutate DSH configuration behind its service. Existing draft APIs remain available.

## Per-annotation handwriting

- `handwriting_get {id,annotation_id}` returns `{note:null|{id,parent_id,board,transcript,transcription_source,version},annotation}` for one unambiguous source annotation. `board` contains `{width,height,strokes:[{points:[[x,y],...],color,width}]}` in board coordinates, independent of page rotation.
- `handwriting_save {id,annotation_id,board,transcript,transcription_source,expected_version,request_id}` stores or updates one standard FileAttachment reply containing inert SVG with exact stroke metadata. Dimensions are 1–4096, at most 128 strokes / 8,192 finite points, stroke width 0.5–16, board JSON ≤256 KiB and generated SVG ≤768 KiB. Empty strokes retain a corrected text-only board. Transcript ≤12,000 characters; source is `none` (empty text), `model` or `edited`. The editor starts at 640×360 and supports recovered board sizes. The bridge caps requests at 512 KiB.
- `expected_version:null` creates only if no existing note; otherwise require its SHA-256 version. A lowercase UUID `request_id` makes an identical lost-ack retry a no-op. Reusing an ID with different content or a stale version fails without rewriting PDF. Deleting a parent deletes only its owned handwriting reply, preserving external replies. `/Contents` labels transcription provenance; `/IRT` binds its parent. Parent source versions and character budgets include the handwritten summary; child attachment rows are excluded from selectable-note totals.
- Host-only `handwriting_recognize {id,annotation_id,image,request_id}` uses the authoritative paper Session model. `image` is canonical PNG base64, 640×360 or 1280×720, ≤2 MiB. The native attachment service fully decodes it. A prepared Harness call must explicitly support `image`; text-only/unknown routes fail visibly. Returns `{text,provider,model,generated:true,request_id,replayed,...}`. The browser first saves the board, then saves complete generated text with another version-checked write; corrected text is retained unless the user explicitly requests new recognition.
- Recognition concurrency is 2, admission 8, deadline 120 seconds. Private `handwriting.result:*` receipts bind request identity to source and image hash. Complete results replay without generation; definite failure allows explicit new request; uncertain pending never silently reissues. Original board/image state is not placed in catalog rows or recognition receipts. No credentials or browser-supplied model route are accepted.
- Host drafts use hashed `reader:handwriting:*` keys; `reader:handwriting-preferences` stores the automatic-recognition choice. Parent `readerSnapshot.handwritingDraft` is strictly bounded, strips arbitrary/image/config fields and preserves board/version/retry identity through iframe replacement. Unacknowledged process-wide shutdown remains outside that guarantee.


## Durable Ink queue (host only)

- `ink_queue_enqueue {batch:{paperId,parentId?,page,annotation_id,revision,paths,width,color,attempted?}}` returns `{job,duplicate?,limits}` only after atomic host staging. The immutable native request keeps its original lowercase UUID. Identical retry is safe; different geometry under the same ID is a conflict. Legacy `attempted:true` is admitted as uncertain until explicit retry.
- `ink_queue_list {id?}` returns `{jobs,receipts,usage,limits,truncated,error?}`. Each job includes its bounded frozen `batch` and status `queued|writing|saved|uncertain` (`staging` is an incomplete admission recovery state). Pending geometry is prioritized. `receipts` is the complete compact identity/status list from the same snapshot, even if saved geometry exceeds the 1 MiB response budget.
- `ink_queue_retry {annotation_id}` retries the original stored request. Unknown PDF outcomes block later jobs for that paper, while other papers can progress. The worker receives no browser AbortSignal. Startup resumes queued work; interrupted writes become uncertain.
- Limits: 64 strokes /4096 points /128 KiB per batch; 8 pending batches /256 KiB per paper; 4 papers /16 batches /1 MiB total pending; linked saved+reserved geometry keeps the 64 objects /128 strokes /8192 points /256 KiB parent limits. Native geometry bytes are reserved conservatively. Private CAS metadata plus 32 reusable payload slots bounds disk growth; 16 recent saved receipts are retained. Browser state APIs cannot access `ink-queue:*` keys.
- `status.durable_ink_queue` advertises availability. Queue state is temporary recovery state; native PDF `/Ink` and `/IRT` remain authoritative. Backup and atomic replacement, external annotations and original input preservation continue through the existing PDF worker.

### Local handwriting diagnostics

- `ink_diagnostics_append {events}` accepts at most 32 events per call and retains the last 256 in the private `ink-diagnostics:recent` state record. It is CAS-protected across windows. Only defined event names, numeric counts, bounded internal IDs, input type, timestamp and reason/status codes are retained; document text and geometry are discarded.
- `ink_diagnostics_get {}` returns `{schema:1,limit:256,events}` without starting a PDF worker or model. The reader buffers events off the pointer-move path and offers **笔输入 → 导出手写诊断**; if the host is unavailable the export still includes bounded client events. This is best-effort recent history, not a complete audit log or an annotation store.
- `node scripts/diagnose-live-ink.mjs --log PRIVATE_HOST_LOG --port PORT --output PRIVATE_REPORT` compares retained queue batches with native PDF Ink through authenticated local APIs. It records opaque identifiers, counts and comparison results, never tokens, document text or coordinates. It never enqueues/retries a write or invokes a model. The existing queue-list endpoint may resume host-owned pending work; the report explicitly marks omitted or truncated evidence. A match cannot prove that a stroke lost before staging ever existed.

## 画板论文流程工作区

文献／画板／写作／阅读项目目录及双向关联浏览使用独立的只读 `workspace_catalog`、`workspace_related`，分页、关系来源及有限扫描契约见[内容导航](workspace-navigation.md)。它们不修改画板、源文件、阅读项目或编译版本。

`board_flow_snapshot {id,paper_id,flow_id,node_id? 或 node_ids?,expected_revision,max_characters?}` 只读出已保存且修订一致的源流程，生成不可变 `board-ref:` 材料。省略节点为整图；节点列表为原始节点标识，最多 100 个，沿显式关系提取全部可达上下游，环安全且不自动加入旁支。预算 500–24,000 字符，返回现有快照字段及 `flow`、`totals`、`included`、`partial`、`omitted`；截断声明不算完整覆盖。复用 `board_snapshot_get` 验证与既有 DSH 引用预算，读者入口不发送或调用模型。

画板和流程的读者批注使用 `board_annotations_list {id}`、`board_annotations_create {id,target,comment,expected_revision}`、`board_annotations_update {id,note_id,comment,expected_revision}`、`board_annotations_delete {id,note_id,expected_revision}`，返回 `{id,revision,notes}`。目标为 `{kind:'board',node_ids?:[最多40个画板节点],x?,y?}` 或 `{kind:'flow',paper_id,flow_id,node_id? 或 node_ids?:[最多100个流程节点]}`，省略节点为整图。创建时从已保存源提取标题与摘录；列表增加 `stale` 标记，目标删除不抹掉旧摘录。每条文字最多4,000字符、摘录2,000字符，每板200条／240KiB；独立 `board-annotations:` 记录与 CAS，不改变 PDF、画板或流程。通用 `state_*` 拒绝此命名空间，模型工具不能代替读者写批注。

`board_flow_get {id}` 与 `board_flow_save {id,workspace,expected_revision}` 管理独立的 paper-flow-workspace，返回 `{id,workspace,revision}`。首次为空工作区与修订 0；保存采用既有本地存储的锁、原子替换与 CAS。父画板必须存在，删除父板不清除附属记录，通用 `state_*` 不放行此命名空间。192 KiB 与图复杂度在校验／布局前检查，规范化后再次检查保存大小；读取和保存不调用 PDF worker 或模型。旧节点板、源文件与引用格式保持原语义。完整契约、恢复边界与复现入口见 [paper-flow.md](paper-flow.md)。

## 阅读百科

- `encyclopedia_list`：`query?`、`sort?`（term_asc / term_desc / created_desc / created_asc / updated_desc）、`offset=0`、`limit=30`（最多 50），返回 `{items,total,offset,hasMore,truncated}`。本地扫描上限 5000，匹配词条、别名和释义；括号缩写分别匹配，不调用模型或外部服务。仅读取当前页完整条目。
- `encyclopedia_put`：`term`（200 字符）、`kind`（term / concept / organization / abbreviation / person）、`aliases`（最多 20 条）、`definition`（12000 字符）、`expected_revision`（新建为 0）、可选 `source:{paper_id,page,annotation_id?,quote}`。每条最多 60 个来源，引用最多 2000 字符；重复来源合并，过期修订拒绝覆盖。按规范化词条去重，保存为人工整理，来源原文不自动冒充释义。
- 词条保存在既有资料库隔离的本地状态中，与 PDF 原批注独立。Wiki 浏览器共用 `vocabulary_list/update` 展示难词，保留 AI／人工释义标记。`[[词条名]]` 是本地词条检索链接。

### 草稿保存专用入口

`POST /api/paper-library/state`（独立模式为 `/state`）仅接受 `state_get/put/list`，沿用认证、同源检查、状态命名空间与修订冲突保护。请求上限 512 KiB，并发上限 8；普通 `/api` 的两个长任务名额不占用该入口。浏览器新增允许精确的 `workspace:last:<main 或文献 ID>` 状态键，其他内部命名空间仍不可读写。客户端控制并发 keepalive 总量，不自动覆盖其他窗口的冲突；读取失败后可用重试／flush 恢复。

插件对话渲染使用本地构建的 Marked／DOMPurify；允许文本 Markdown 结构，禁用脚本、嵌入框架与图片，链接仅保留 HTTP(S)／mailto。选文或普通问题的已记录来源快照也能触发完整回答的自动 PDF 保存；无来源的其他主对话消息不继承上一轮批注。
