# 研究难点挖掘：把“语言现象”变成可复核的领域难点

2026-09-17。性质：设计草案（未实施）。本文记录外部依据的核实范围、与本项目现有能力的映射、四阶段管线、预算与不变式。评审通过后再进入实施。

## 0. 结论速览

- 本项目**目前没有**跨文献的难点/局限挖掘能力：现有的是**单篇**整理（图谱草稿、精读笔记）与**元数据级**全库构建（`references.bib` + 身份审计）。两者的产物里已有 `gap`、`question`、`claim`、`evidence` 等类型，但没有把它们聚合成“领域共性难点”。
- 外部存在三条成熟路线可借鉴：**研究挑战抽取**（HCI 语料）、**局限识别与生成**（BAGELS 基准）、**知识缺口映射**（GAPMAP）。
- 建议做法：**确定性候选挖掘（无模型）→ 单篇受限抽取（模型 + 精确原文/页码）→ 跨篇主题聚合（可审阅草稿）→ 复核与导出**。前两步就能落地，且完全落在现有契约内。
- 最大风险不是技术，而是**把“AI 推断的隐含局限”写成“作者承认的局限”**。因此设计上把 `source_status`（作者自陈／审稿人指出／模型推断）作为一等信息，并禁止跨级冒用。

## 2. 与本项目现有能力的映射

可直接复用（已在代码中验证）：

| 现有能力 | 位置 | 复用方式 |
|---|---|---|
| 受限分页读取（≤8 页、≤8 段、24,000 字符/批） | `src/dsh_paper_library/paper_analysis.py` | 难点挖掘的文本来源，天然有界 |
| 隔离子代理（禁工具、120 秒、独立父会话） | `src/harness/paper-analysis-agent.mjs` | 单篇抽取的执行体，不需要新沙箱 |
| 类型化草稿 + 精确引用 + 页码（`gap`/`question`/`claim`/`evidence`/`observation`） | `src/dsh_paper_library/library_knowledge.py` | 难点记录直接落在既有类型上，不新造平行模型 |
| 只读结构检查（`knowledge_draft_lint`） | 同上 | 新增“主题证据充分性”规则即可 |
| 审阅界面（接受/否决/笔记） | `web/knowledge-workflow.js` | 主题草稿沿用同一审阅动作 |
| 页面跳转与批注联动 | `web/pdf-reader.js`、`web/app.js` | 主题证据点开即跳到原文页并闪示 |
| 有界并发队列 | `src/harness/paper-analysis-queue.mjs` | 跨篇批量抽取的调度骨架 |

确实缺失（本设计要补）：

1. **小节定位**：现有抽取只按页码切块，不识别 Introduction / Discussion / Limitations / Future Work / Conclusion。
2. **触发词与句式扫描**：没有任何确定性候选挖掘。
3. **来源分级**：草稿节点没有 `source_status`（作者自陈／审稿人／推断）。
4. **跨篇聚合**：没有“同一难点被 N 篇论文提到”的统计、聚类与排名。
5. **语料级视图**：库界面只有逐篇的图谱与审计，没有领域级难点面板。

## 3. 设计

### 3.1 对象：难点记录（ChallengeRecord）

不新增第六套存储，直接扩展既有草稿契约：

- 节点仍用 `gap`（未解决的缺口）与 `question`（开放问题）两种类型；新增可选字段 `source_status`：
  - `author-stated`：原文明确承认的局限/挑战（必须逐字引用）；
  - `reviewer-stated`：审稿意见指出的问题（仅当我们导入了带位置的审稿文本时可用，否则不出现该状态）；
  - `inferred`：模型从上下文推断的隐含难点（**必须**带推断依据与原文引用，且在界面与导出中单独分组）。
- 每条难点附 `fields`（受界标量）：`target`（方法／数据／场景／评测／伦理）、`paper_role`（作者是否自认）、`asked_by`（方法提出者／使用者）。
- 证据仍走 `evidence` 节点 + 精确 `quote` + 真实 `locator.page`；断言沿用 `identifies` / `motivates` / `limits` / `blocks` 等既有受控关系。
- 主题（Theme）是**跨篇聚合结果**，不是新节点类型：以“归一化标签 + 成员难点 ID 列表 + 覆盖统计”记录在独立的语料级草稿中，状态一律 `needs-review`。

### 3.2 管线

```
显式选择语料（≥3 篇，≤50 篇/次）
        │
P1 确定性候选挖掘（无模型）
  小节定位 + 触发词/句式扫描 → 候选段落（论文 + 页码 + 原文 + 命中规则）
        │
P2 单篇受限抽取（模型，隔离子代理）
  候选段落 → 难点记录（source_status + target + 精确引用 + 页码）
        │
P3 跨篇聚合（确定性优先，必要时模型辅助，全部待审阅）
  归一化标签聚类 + 主题合并建议 → 主题草稿（覆盖篇数、年份分布、代表引用）
        │
P4 复核、对照与导出
  审阅界面 + 结构检查 + 与自有清单/征稿主题对照 + CSV/Markdown/BibTeX 导出
```

各阶段的确定性/模型边界必须写进界面文案：P1 完全离线可复现；P2、P3 使用模型额度且产物一律待审。

### 3.3 预算与边界

- 一次运行最多 50 篇、每篇最多扫描 6 个目标小节、每篇候选段落 ≤40 条、每条 ≤1,200 字符；总量不超过单篇 24,000 字符的既有读取预算。
- **不做全库自动扫描**：必须由用户显式选择范围（当前检索结果、手选集合或导入批次）。
- 候选挖掘不打开 PDF 以外的任何网络资源；不引入向量库；跨篇聚合默认用确定性归一化匹配，模型只用于“合并同一主题”的建议，且必须逐条审阅。
- 失败与中断沿用现有纪律：已完成的单篇结果保留，不确定的模型调用不自动重放。

### 3.4 界面与导出

- 新增「研究难点」面板（与「知识图谱」并列的第三个库级视图）：
  - 顶部：本次语料条数、覆盖年份、命中规则分布、未读/失败清单；
  - 主题列表按覆盖篇数排序，展开显示成员难点（论文、页码、原文引用、来源分级）；
  - 每条证据可点击跳回 PDF 对应页并闪示（复用既有联动能力）；
  - 「来源分级」开关：默认只看作者自陈，推断类单独分组并明确标注。
- 导出：`challenges.csv`（主题 × 论文 × 引用 × 页码 × source_status）、`challenges.md`（可读报告）、以及引用键清单（便于把“难点 → 相关文献”带回写作）。

### 3.5 验证与不宣称

- 可自动验证的部分：小节定位与触发扫描的合成夹具、每篇配额、source_status 的引用可核验性（引用必须逐字出现在来源快照中）、跨篇统计口径、导出字段完整性、中断恢复。
- **不能**用插件测试替代的部分：抽取质量、主题合理性、与人类判断的一致性。κ 一类指标需要真实标注者与人工研究，插件只能提供可复现的导出供其测量。
- 明确不宣称：不宣称“自动科研发现”，不宣称覆盖领域全貌；产物是**待核对的难点候选**，其价值取决于读者判断。

### 3.6 不变式（红线）

1. 任何难点陈述都必须能追溯到来源快照中的逐字引用与真实页码；没有就留空，不补写。
2. `author-stated` 与 `inferred` 不得混排或互相顶替；界面上必须有可视区分。
3. 主题与难点一律 `needs-review`，插件不得自动接受、不得自动写入知识笔记正文。
4. 不引入第二套模型/密钥配置；沿用论文当前 DSH 模型与会话。
5. 不新增常驻服务、向量库或全库后台任务。

## 4. 分阶段实施建议

| 阶段 | 范围 | 主要产物 | 验收标准 |
|---|---|---|---|
| P1 | 小节定位 + 触发词/句式扫描（无模型） | 候选段落列表 + 命中规则回执；`challenges-candidates` 视图或导出 | 合成 PDF 上小节/触发命中可复现；零模型调用；每篇配额生效 |
| P2 | 单篇受限抽取（复用隔离子代理） | 单篇难点草稿（`gap`/`question` + `source_status` + 证据） | 引用逐字可核验；中断不重放；lint 覆盖“难点必须有证据” |
| P3 | 跨篇聚合与语料级视图 | 主题草稿 + 覆盖统计 + 「研究难点」面板 + 导出 | 覆盖篇数/年份统计与草稿一致；主题合并建议待审；导出字段完整 |
| P4 | 对照与质量评估 | 与自有清单/征稿主题对照报告；人工评审包 | 报告只陈述可核验结果；κ 类结论留给人工研究 |

本设计的 P1 与 P2 互不阻塞：P1 不需要模型，可先做；P2 需要用户确认是否将模型额度用于批量抽取。

## 5. P1 的最小可行性验证（已跑通）

在合成论文（`synthetic-challenge-paper.pdf`，2 页、含 8 个小节标题与若干触发句）上用**现有依赖**（PyMuPDF）跑确定性子节 + 触发词扫描：

- 结果：识别 **8 个小节**（Abstract / 1 Introduction / 2 Related Work / 3 Method / 4 Results / 5 Discussion / 6 Future Work / 7 Conclusion），命中 **5 条触发句**并各自带真实页码（`however` / `fail to` / `limitation` / `despite` / `remains unclear` / `future work` / `challenge`）。
- 成本：**零模型调用、零新增依赖**；同一份夹具可直接作为 P1 的回归测试输入。
- 发现的实现要点（写进 P1 需求）：PDF 文本抽取会把小节标题与正文行粘连，naive 的按句切分会把标题并入候选句（例如 “However, they fail to generalise … 2 Related Work Prior synthetic work lacks …”）。因此 P1 必须按**小节边界分段**，再在小节内部按行/段落切分，并对跨行句子做合并；否则候选质量与后续引用核对都会受影响。

该验证只证明**定位与扫描可行**，不构成抽取质量或领域覆盖的结论。

## 6. HCI 方向的专门说明

用户关注 HCI/IJHCI 那套流程，若要以 HCI 语料为目标，本设计的差异点在于：

- 该工作的两步法（先广抽、再逐篇筛选）可直接映射到 P1+P2：P1 的触发扫描相当于其“广抽”的确定性替代，成本更低且可审计；P2 的逐篇筛选对应其第二步。
- 它用**主题建模**把 4,392 条挑战压到 113 个主题；我们的 P3 用“归一化标签 + 覆盖统计”，先保证可复核，模型只做合并建议。若后续需要更接近其效果，可再加可选的本地聚类（仍不引入常驻向量服务）。
- 它把结果与 **HCI grand challenges 与 SDG** 对照，发现“人机协作”等方向存在缺口。类似做法在我们的语境里是：把挖掘结果与用户自己的清单（如 `PhDPlan.md`、征稿主题、审稿意见）对照，输出缺口报告——这部分属于 P4，且必须注明对照清单的来源与日期。
- 成本参照：其全语料（879 篇）约 US$50。我们的插件按单篇受限读取，成本随所选语料线性增长；实施时应先在 10–20 篇上做校准，再决定批量规模。
